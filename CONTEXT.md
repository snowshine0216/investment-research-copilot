# Investment Research Copilot — Domain Glossary

Canonical terms used in the opportunity / memo / discipline pipeline. Pointed to by the diagnosis doc, the workflow diagram, and code reviews. This file is a glossary, not a spec.

## Evidence & citation

- **Active fund** — an actively-managed CN equity fund (`asset_class="cn_equity_fund"`). The disclosed top-N holdings reflect manager judgement, so each holding receives its own evidence record. Subject to the **drill-through requirement**: per-constituent data + information legs (filing/NAV + broker/news).
- **Passive ETF / tracked index** — `asset_class="cn_etf"` or a tracked CN index. The fund is rule-based, so per-constituent qualitative evidence is **not** required. Investability is described at the **fund level**: NAV/return metrics as the data leg, ETF announcement (or `fund_announcement_em`) as the information leg. The "ANALYZE ONE by ONE" mandate does not apply to passive vehicles.
- **Drill-through requirement** — top-N holdings of an **active fund** must each carry their own data + information leg evidence. Does not apply to passive ETFs or tracked indices.
- **Data leg** — quantitative primary evidence (`citation_kind="data"`): filing digest, fund NAV report. Not opinion-derived.
- **Information leg** — narrative or opinion-bearing evidence (`citation_kind="information"`): broker report, news item, fund announcement. Filing-only never satisfies it.
- **Dual-coverage gate** — a publishable opportunity row requires ≥1 data-leg AND ≥1 information-leg citation, both from `scope in {"instrument", "constituent"}` and both with `owner_instrument_id == row.instrument_id`. Macro/policy scope alone never satisfies either leg.
- **Citation scope** — `instrument` (about the fund itself) | `constituent` (about a held stock) | `asset_class_macro` (theme report) | `policy` (regulatory). The first two are gate-satisfying; the latter two are supplemental.
- **Citation ID** — 16-char sha256 of `(owner_instrument_id, scope, constituent_key, type, canonical_url_or_fallback, date)` where `canonical_url_or_fallback` is the URL, or `source:date:summary[:64]` when URL is empty. 64 bits ⇒ collision-resistant (≤2.7e-10 for ≤100k/run) but not collision-proof; the `build_cited_map` duplicate-id detector raises immediately if a collision ever fires. See [ADR 0001](docs/adr/0001-citation-data-model.md).
- **Scope precedence** (for selector tie-breaking and "fill-remaining" slots): `instrument > constituent > asset_class_macro > policy`. The instrument/constituent pair are the only scopes the dual-coverage gate accepts; macro/policy never satisfy the gate but appear in the fill-remaining tail.
- **Citation selector priority** (deterministic; used by the picks table and evidence pool to pick ≤3 citations per instrument): sort key per entry = `(scope_rank, kind_rank, holding_weight_pct, iso_date_recency, citation_id asc)`. The data slot picks the top `kind="data"` entry; the info slot picks the top `kind="information"` entry; remaining slot is filled by the same key minus the kind component. Two shuffled input orders must produce the same 3-entry output.
- **Contributing dimensions** — the subset of `{valuation, heat, thesis, product_quality}` whose sub-state drove the final `opportunity_state`. Derived deterministically from the four sub-states by `derive_contributing_dimensions` (Slice A0); never populated ad-hoc. The dual-coverage gate iterates this set so that each driver of the conclusion is independently cited.

## Active-fund fetch engine

- **`FundHolding`** — one disclosed top-N holding of an active fund: `(symbol, name_cn, weight_pct, exchange, provider_symbol)`. `weight_pct` is in **percent units** (0.0–100.0), NOT a fraction. `exchange` is `SH | SZ | BJ | HK | US | UNKNOWN`; the parser stamps `UNKNOWN` rather than guessing when a ticker cannot be resolved. See [ADR 0002](docs/adr/0002-active-fund-fetch-engine.md) §4.
- **`HoldingsResult`** — return shape of `fetch_cn_etf_holdings`: `(constituents: tuple[FundHolding, ...], source_report_date, source_report_quarter)`. The `source_report_quarter` is **provider-declared** (from the `季度` column, e.g. `"2024Q1"`), NOT calendar quarter.
- **`ConstituentAnalysis`** — per-holding structured evidence: `(symbol, name_cn, weight_pct, evidence: tuple[ThesisEvidence, ...], failure_reasons: tuple[str, ...], one_line_view: str)`. Lives on `OpportunityRow.constituent_analyses` and `DisciplineRow.constituent_analyses`. Every `ThesisEvidence` in `.evidence` carries `scope="constituent"`, `parent_fund_id=fund_id`, `constituent_key=symbol`. The audit gate (item 009) reads structured `.evidence`; `one_line_view` is for human consumption only.
- **`ActiveFundSnapshot`** — full per-fund result: `(fund_id, source_report_date, source_report_quarter, cache_probed_at, constituent_analyses, failure_reasons_by_symbol, fund_level_failure_reasons, fund_level_evidence)`. Distinct from the legacy `ConstituentSnapshot` (which still serves passive ETFs / tracked indices). Cache layout: `data/fundamentals/{source_report_quarter}/active_fund/fund_{iid}.json`. See [ADR 0002](docs/adr/0002-active-fund-fetch-engine.md).
- **`ActiveFundSnapshot.fund_level_evidence`** — `tuple[ThesisEvidence, ...]` (default `()`) carrying fund-level NAV (`citation_kind="data"`, `scope="instrument"`, `owner_instrument_id=fund_id`) and announcement (`citation_kind="information"`, same scope/owner) records, fetched unconditionally by `_build_active_fund_snapshot` via the same `fetch_fund_nav_report` + `fetch_fund_announcements` adapters used by `_build_fund_level_snapshot`. Deliberately named DIFFERENTLY from `FundLevelSnapshot.evidence` so the cache serialiser can't conflate the two. Consumed by Policy B rule 2.5 (foreign-heavy short-circuit). Older cache files missing the field re-hydrate with `()` — graceful migration, no manual cache invalidation. See [ADR 0003](docs/adr/0003-failure-mode-policy-b.md) §7.
- **Disclosure quarter** — the fiscal quarter the provider attributes a holdings disclosure to (e.g. `2024Q1` for a March-end report). Distinct from **calendar quarter** (when the fetch ran). Cache keys, freshness checks, and audit comparisons always use disclosure quarter.
- **Fail-closed freshness probe** — when a cached `ActiveFundSnapshot` is older than `IRC_CACHE_FRESHNESS_DAYS` (default 7) on a canonical run, fire a probe (`fetch_cn_etf_holdings(provider_symbol, top_n=1)`). Probe failure (exception or empty) forces a full refetch — never silently reuses stale data. Probe succeeding with the same quarter advances `cache_probed_at` and reuses the body. See [ADR 0002](docs/adr/0002-active-fund-fetch-engine.md) §2.
- **Preflight fetch budget** — `IRC_FETCH_BUDGET` (default 2000) caps total AkShare calls per run. Computed at `_build_rows` entry BEFORE any per-instrument fetch; a single hard gate, no mid-loop checks. Plan-hash-keyed resumable state file (`data/fundamentals/.fetch_state_<hash>.json`) lets interrupted runs resume.
- **Forbidden adapter pair** — for a given `FundHolding.exchange`, certain adapters MUST NOT be called (e.g. `fetch_cn_broker_reports` for HK constituents). Misrouting returns nonsense data without a provider error. Enforced by the dispatcher's branch structure and locked by tests. See [ADR 0002](docs/adr/0002-active-fund-fetch-engine.md) §4.

## Fund-level fetch engine

- **`FundNavReport`** — fund-level NAV time series snapshot: `(fund_id, fund_name, latest_nav, latest_nav_date, nav_history, source_report_quarter)`. `latest_nav_date` is ISO 8601 `str` (converted from AkShare's `datetime.date` at the adapter boundary). `source_report_quarter` is derived from `latest_nav_date` via `infer_quarter` (calendar-quarter rule reused from ADR 0002 §1 for NAV, since NAV is a daily series with no provider-declared disclosure quarter). The data-leg of the dual-coverage gate for gold / cn_bond_fund / cn_etf / tracked CN ETF rows.
- **`FundAnnouncement`** — one fund-specific announcement record: `(fund_id, title, topic, date, report_id)`. `topic` is `Literal["dividend", "report", "personnel"]` — the endpoint origin. `date` is ISO 8601 `str` (normalised from AkShare's `datetime.date`). `report_id` is the opaque `报告ID` provider reference; there is **no URL column** in AkShare 1.18.63's topic-specific announcement endpoints, so `ThesisEvidence.url=""` and the citation-id preimage falls back to `summary[:64]` (per ADR 0001 §2), with `summary = f"[{report_id}] {title}"` to make the discriminator participate in the hash.
- **`FundLevelSnapshot`** — full per-fund result for **non-active** V1 asset classes: `(fund_id, nav_report, announcements, evidence, source_report_quarter, cache_probed_at, fund_level_failure_reasons, evidence_gaps)`. Distinct from `ActiveFundSnapshot` (which has per-constituent analyses) and `ConstituentSnapshot` (legacy display-only). `nav_report` is `None` when NAV fetch failed or for the QDII sentinel. Cache layout: `data/fundamentals/{source_report_quarter}/nav/fund_{fund_id}.json` — parallel to `active_fund/` per ADR 0002 §5.
- **Fund-level dispatch** — `build_snapshot` routes by `LookthroughTarget.kind`: `active_fund` → `_build_active_fund_snapshot` (item 003); `qdii_us`/`qdii_hk`/`qdii_global` → `_build_qdii_sentinel_snapshot` (in-process, zero-fetch); `gold`/`bond`/`broad_index`/`sector_theme` with non-empty `provider_symbol` → `_build_fund_level_snapshot`; else legacy display-only `_build_legacy_snapshot`. The dispatch keys off `target.kind` only — never `target.key` or `target.display_cn`. See [ADR 0002](docs/adr/0002-active-fund-fetch-engine.md) §5.
- **QDII V1 exclusion** — every `qdii_us`/`qdii_hk`/`qdii_global` `LookthroughTarget` produces a sentinel `FundLevelSnapshot` with `nav_report=None, announcements=(), evidence=(), evidence_gaps=("qdii_information_unavailable",)`. Zero AkShare calls fired. The sentinel is **NOT cached on disk** (gap-only rows have nothing to cache; in-process re-emission is cheaper than I/O). Item 006's H3 universal-gap invariant routes these rows to the discipline failure section only.
- **Static-profile invariant** — the `ak.fund_open_fund_info_em(symbol, indicator="基金概况")` indicator is **NEVER** consulted by the production engine. Fund profile text is static metadata, not a time-bound communication; if it satisfied `citation_kind="information"` it would silently bypass the freshness intent of the information leg. The invariant is enforced **upstream at the adapter layer** — `fetch_fund_nav_report` only calls `indicator="单位净值走势"` and the information leg only emits via `fetch_fund_announcements`. No downstream gate enforcement is required (or possible — `ThesisEvidence` carries no `indicator` field). Locked by an acceptance test that greps for `"基金概况"` in production code.

## Failure-mode + audit policy

- **`failure_reasons` (adapter-level)** — per-constituent diagnostic strings emitted by item 003's adapters when a fetch raised or returned empty (e.g. `"filing_fetch_failed:600519:ConnectionError"`, `"broker_empty:00700"`). Lives on `ConstituentAnalysis.failure_reasons` and on `ActiveFundSnapshot.failure_reasons_by_symbol`. Semantic: "the adapter ran but couldn't produce evidence." Item 006's Policy B reads these to distinguish rule-3 (no data leg) from rule-5 (mixed evidence + failure_reasons) cases.
- **`evidence_gaps` (row-level)** — fund-row-level gap codes on `OpportunityRow.evidence_gaps` (and mirrored on `FundLevelSnapshot.evidence_gaps`). Stamped by items 003 (structural gaps), 005 (QDII sentinel, fund-level failures), and 006 (Policy B). Semantic: "the fund as a whole cannot publish." H3 (item 006) routes any row with non-empty `evidence_gaps` away from `thesis_cards.yaml` + `opportunity_report.json.rows` and into the discipline failure section. Distinct from `failure_reasons` (which is per-constituent diagnostic), `audit_errors` (per-constituent shape-corruption), and `advisory_gaps` (row-level non-blocking advisories). Codes that should warn the operator without blocking publication go into `advisory_gaps`, NEVER `evidence_gaps`.
- **`audit_errors` (per-constituent shape-corruption)** — `tuple[str, ...]` field on `ConstituentAnalysis` (default `()`). Populated by item 006's Policy B when a constituent has BOTH `evidence==() AND failure_reasons==()` — item 003's adapter contract was violated (the constituent was emitted with no evidence and no diagnostic). Format: `"missing_constituent_record:{symbol}"`. Distinct from `failure_reasons` (adapter ran but no evidence) and `evidence_gaps` (row-level disposition). Item 009's `find_incomplete_constituent_analyses` raises on the same predicate as defence-in-depth. The original cached `ConstituentAnalysis` JSON is never mutated — Policy B derives the audit error on evaluation and stamps it on a fresh `ConstituentCoverageEntry` for the rejection record.
- **`advisory_gaps` (row-level non-blocking)** — `tuple[str, ...]` field on `OpportunityRow` (default `()`). Semantic: "evidence quality concern the operator should see, but the row is still publishable." Distinct from `evidence_gaps` (row-blocking; H3 routes to gapped_rows), `expected_omissions` (structural non-features by design — e.g. `constituent_not_applicable`), and `failure_reasons` (per-constituent adapter-level diagnostics). H3 partition predicate is unchanged: `evidence_gaps == ()` alone decides publishability; `advisory_gaps` is orthogonal and carried through into publishable outputs. Codes live in module-level `ADVISORY_GAP_CODES: frozenset[str]` in `src/irc/opportunity/states.py`; `_partition_gaps` becomes a 3-way split returning `(real_gaps, expected_omissions, advisory_gaps)`. May coexist with Policy B rule 2.5 acceptance — e.g. a foreign-heavy active fund can be publishable via rule 2.5 AND carry `top_holdings_broker_thin` simultaneously; both are correct. See [ADR 0005](docs/adr/0005-advisory-gaps-field.md).
- **`top_holdings_broker_thin`** — `advisory_gaps` code emitted by `derive_thesis_from_evidence`'s `ActiveFundSnapshot` branch when an active fund's top-5 holdings have weak broker coverage: `count_broker_empty_top5 >= 2` OR `weight_broker_empty_top5 >= 20.0` (percent units, disjunctive). "Top-5" is the weight-rank prefix with boundary-tie extension mirroring `MATERIAL_HOLDING_QUORUM` precedent. Counted symbols are those whose `failure_reasons` contains an entry matching `broker_empty:*`. Constants `TOP_HOLDINGS_BROKER_THIN_COUNT_THRESHOLD = 2` and `TOP_HOLDINGS_BROKER_THIN_WEIGHT_PCT_THRESHOLD = 20.0` are module-level `Final` (hardcoded by design, same precedent as `FOREIGN_HEAVY_THRESHOLD`). Active-fund only — never emitted for `FundLevelSnapshot` (passive ETF / gold / bond / QDII sentinel) because passive vehicles have no per-constituent broker fetch path. Companion to `missing_broker_coverage` (legacy `ConstituentSnapshot` blocking gap); `top_holdings_broker_thin` is advisory, not blocking.
- **`MATERIAL_HOLDING_QUORUM`** — the formula `ceil(top_N / 2)` used by Policy B to determine the material top-half of a fund's holdings ranked by `weight_pct` descending. For `top_n=10` the material set has 5 holdings, EXTENDED to include any holding whose `weight_pct` equals the cutoff weight (tied at the boundary). Exposed as a module-level `Callable[[int], int]` from `src/irc/opportunity/rejection_log.py` so future asset classes can swap the formula.
- **Material top-half** — the `MATERIAL_HOLDING_QUORUM`-sized subset of an active fund's holdings, ranked by weight descending with boundary-tie extension. Each holding in the material set must satisfy the info-leg requirement; tail holdings (weight rank > material size) are data-only-permitted. The set is the gate for Policy B rule 4.
- **Policy B (weight-aware quorum)** — the audit policy that decides whether an `ActiveFundSnapshot` is publishable. Pure function `evaluate_policy_b(snapshot, *, top_n)` in `src/irc/opportunity/policy_b.py` returns a `PolicyBVerdict` carrying `gap_codes`, `audit_errors`, `decision_rule`, `material_symbols`, and `constituent_coverage`. Applies ONLY to `ActiveFundSnapshot` — `FundLevelSnapshot` (gold/bond/cn_etf/QDII-with-provider_symbol) and `ConstituentSnapshot` (legacy display-only) do not have per-constituent evidence and are evaluated at the fund-level only. **Six rules** in fixed precedence: (1) holdings_fetch_failed, (2) missing_constituent_record audit error, (2.5) foreign-heavy short-circuit (rule 2.5; see entry below), (3) per-holding data leg required for ALL top-N, (4) per-holding info leg required for material top-half, (5) incomplete_constituent_coverage. See [ADR 0003](docs/adr/0003-failure-mode-policy-b.md) §1 + §7.
- **Foreign-heavy fund (rule 2.5 short-circuit)** — an `active_fund` whose top-N constituents are weight-majority listed outside Mainland China (`exchange in {"HK", "US"}`) at share ≥ `FOREIGN_HEAVY_THRESHOLD` (0.50). Policy B rule 2.5 short-circuits such funds by accepting `ActiveFundSnapshot.fund_level_evidence` (NAV data leg + announcement information leg, both `scope="instrument"`, `owner_instrument_id=fund_id`) as the dual-coverage gate substitute for per-holding filings — because the per-holding CN filing pipeline does not reach HK/US tickers and the fund itself is a publishable CN-registered vehicle. Mirrors the 2026-05-25 QDII fetch reform's evidence shape; differs from QDII by keeping the row on the `ActiveFundSnapshot` path so the `## 持仓明细` appendix still renders per-constituent context. When `fund_level_evidence` is empty, rule 2.5 emits gap code `foreign_heavy_fund_level_evidence_missing`. Foreign share is **derived at evaluation time** by `_compute_foreign_listed_share(ranked)`, never persisted on the snapshot (mirrors the "audit_errors derived, never persisted" principle from ADR 0003 §2). `UNKNOWN` and `BJ` exchanges are NOT counted as foreign. See [ADR 0003](docs/adr/0003-failure-mode-policy-b.md) §7.
- **`FOREIGN_HEAVY_THRESHOLD`** — module-level constant `= 0.50` in `src/irc/opportunity/policy_b.py`. Comparison is `>=` so a fund sitting exactly at 50.0 % foreign weight is accepted. Hardcoded by design (no YAML / env-var knob in V1): operators tuning thresholds at runtime would silently weaken the audit trail. Future promotion to env var `IRC_FOREIGN_HEAVY_THRESHOLD` follows the same pattern as `IRC_CACHE_FRESHNESS_DAYS` without an API change. Companion to `MATERIAL_HOLDING_QUORUM`.
- **`PolicyBVerdict`** — frozen dataclass returned by `evaluate_policy_b`. Stashed in a `pending_verdicts: dict[str, PolicyBVerdict]` accumulator threaded from `_build_rows` to `_write_opportunity_outputs` so the rejection record can be emitted with full verdict context (decision_rule + material_symbols + constituent_coverage) without re-evaluating Policy B. NEVER mutates `OpportunityRow.thesis_state` — that literal is exclusively set by `derive_thesis_from_evidence`.
- **`RejectionRecord`** — frozen dataclass; one entry per excluded fund. Carries `instrument_id`, `name_cn`, `asset_class`, `rejection_reason` (a `Literal` typed `RejectionReasonCode`), `decision_rule` (human-readable, template-format-locked), `rejection_at_stage`, `constituent_coverage: tuple[ConstituentCoverageEntry, ...]` (weight-ranked breakdown with per-constituent `has_data_leg`/`has_info_leg`/`audit_errors`), `fund_level_failure_reasons`, `fetch_types_attempted`, and `evidence_gaps`. Lives in `src/irc/opportunity/rejection_log.py`.
- **Rejection log (`rejections.json`)** — canonical audit trail at `outputs/{date}/rejections.json`. JSON-serialised `RejectionsDocument` (`run_date`, `plan_hash`, `entries: tuple[RejectionRecord, ...]` sorted by `(asset_class, instrument_id)` ascending). Built in-memory and **written atomically once** at the end of `_write_opportunity_outputs` Step 4 via the existing `.tmp.{pid} → os.replace` pattern — NEVER appended per-row (atomic write-at-end is the project convention; partial files are not a tolerated visible state). Empty rejections case writes `entries: []` (the empty file is the signal of "no rejections this run", not a skip).
- **H3 universal gapped-row invariant** — `_write_opportunity_outputs` partitions `kept_rows` into `publishable_rows` (`evidence_gaps == ()`) vs `gapped_rows` (`evidence_gaps != ()`) at the top of the function, after a fatal pre-gate raise on `fetch_budget_exhausted`. `thesis_cards.yaml` and `opportunity_report.json` emit publishable rows only. The discipline_report.md failure section reads only `instrument_id`, `name_cn`, `evidence_gaps`, `fetch_types_attempted` (4 fields) — never `opportunity_state`/`dca`/`risk`/`note_cn`/`thesis_state` etc., because gapped rows have not earned conclusions. The renderer's signature is the enforcement mechanism. The predicate is `evidence_gaps == ()` ONLY — `advisory_gaps` and `expected_omissions` do NOT participate in the partition (advisory codes are visible on publishable rows by design).
- **`fetch_budget_exhausted` (run-level fatal sentinel)** — gap code that may appear in `evidence_gaps` ONLY transiently inside a buggy code path. Item 003's preflight `FetchBudgetExceeded` raises BEFORE `_build_rows` returns (so production-path rows never carry it). Item 006's H3 Step 1 defence-in-depth check raises `RuntimeError` (a distinct exception class from `FetchBudgetExceeded`) the moment a row carrying this code reaches `_write_opportunity_outputs`. Unlike all other gap codes, this one MUST NOT survive into `rejections.json` — its emission is itself a programming error.
- **V1 systematic exclusions** — a once-per-run `## V1 systematic exclusions: N funds excluded due to US-heavy material holdings` line in `discipline_report.md`, emitted UNCONDITIONALLY (zero-count case still renders with N=0 for greppable stability). N counts the `RejectionRecord`s where `rejection_reason == "insufficient_info_coverage_top_half"` AND a strict majority of `material_top_half` constituents have `exchange == "US"`. Computed AND rendered by item 006's `render_v1_systematic_exclusion_summary` — item 007 does NOT recompute. Paired with the §1.2 footnote in `docs/diagnosis-thesis-cards-evidence-gap.md` documenting the V2 prerequisite (a US-info-leg adapter).

## QDII premium-to-NAV

- **QDII premium-to-NAV ratio** — for an on-exchange QDII feeder ETF (`asset_class ∈ {"us_etf","hk_etf","qdii_global"}` AND `market == "cn_on_exchange"`), the **signed** ratio `(secondary_market_price - NAV) / NAV` derived from AkShare's `fund_etf_spot_em()` bulk table via `premium = -(基金折价率)/100.0`. Positive = trading **above** NAV (premium); negative = trading **below** NAV (discount). Sign convention is flipped from AkShare's native `基金折价率` column (which is discount-positive — confirmed by the 3-row 2026-05-26 sample where `513650: 基金折价率=-2.92` represents a 2.92% premium). Stored on the score dict as `qdii_premium_pct` in ratio units (e.g. `0.0292` for 2.92%), NOT percent units. Off-exchange feeders transact at NAV by construction (see "off-exchange synthetic-zero premium policy") and are stamped with the synthetic value `0.0` rather than fetched.
- **`fetch_qdii_premium_pct`** — `src/irc/data/akshare_client.py::fetch_qdii_premium_pct(symbol: str) -> float | None`. The only effectful entry point for premium values. Returns a signed ratio (per "QDII premium-to-NAV ratio") on success, `None` on AkShare exception / empty table / missing required columns (`代码`, `基金折价率`) / symbol-not-in-table (degrade-to-None contract from ADR 0002 §5). Dispatches through `_fetch_full_etf_spot_table()` which is `lru_cache(maxsize=1)`-decorated so all QDII symbols in a single `irc run` share ONE AkShare call. Tests must call `_fetch_full_etf_spot_table.cache_clear()` in teardown to prevent fixture leakage between tests (same pattern as `_fetch_full_fund_table` / `_fetch_full_etf_table` / `_fetch_full_fund_rank_table`).
- **Off-exchange synthetic-zero premium policy** — when `asset_class ∈ {"us_etf","hk_etf","qdii_global"}` AND `market == "cn_off_exchange"`, the scoring pass stamps `qdii_premium_pct = 0.0` WITHOUT invoking `fetch_qdii_premium_pct`. Off-exchange QDII feeders (open-ended LOF / FOF units) transact at NAV by construction — subscription/redemption settle at end-of-day NAV, so the secondary-market premium concept does not apply. `None` would falsely fire `qdii_premium_unknown` and re-block these structurally-NAV-tracking funds; `0.0` correctly clears both `qdii_premium_unknown` (value is known) and `qdii_premium_too_high` (`0.0 ≤ threshold`). Implemented by `src/irc/scoring/qdii_premium.py::qdii_premium_for_row` as a routing helper that returns `0.0` before calling the fetcher.
- **`qdii_premium_too_high`** — gate-blocking reason code emitted by `compute_blocking_reasons` in `src/irc/decision/gates.py` when `asset_class ∈ {"us_etf","hk_etf","qdii_global"}` AND `score.get("qdii_premium_pct") is not None` AND `qdii_premium_pct > qdii_max_premium_pct` AND `score_action ∈ {"buy_candidate","strong_buy_candidate"}`. Peer of `qdii_premium_unknown` but operator-semantics distinct: `qdii_premium_unknown` means "fetch failed, data not available — refresh the snapshot"; `qdii_premium_too_high` means "data available, market itself is unfavourable — wait or use alternative venue". The two codes are MUTUALLY EXCLUSIVE in any single call (a `None` premium cannot also be "too high"). Surface in `_BLOCKING_REASON_LABEL` and `_BLOCKING_REMEDIATION` in `decision/report.py`.
- **`qdii_max_premium_pct`** — operator-tunable threshold in `config/discovery.yaml::hard_filters.qdii_max_premium_pct`, schema `src/irc/schemas/discovery.py::HardFilters.qdii_max_premium_pct: float = Field(default=QDII_MAX_PREMIUM_DEFAULT, gt=0, le=1)`. Default `QDII_MAX_PREMIUM_DEFAULT: Final[float] = 0.05` (5% premium ceiling; matches the existing `qdii_premium_unknown` remediation text "QDII feeders frequently trade 5–15% above NAV"). Units: ratio, not percent. Comparison is strict-greater (`premium > threshold` blocks; equality at the boundary is accepted, mirroring `FOREIGN_HEAVY_THRESHOLD` precedent). Hardcoded `Final` constant in `schemas/discovery.py` so the magic number has a name; YAML override is the operator surface. **`gt=0` invariant:** zero is never a meaningful threshold — it would silently block every QDII buy candidate with any positive premium; Pydantic rejects `0` and negatives at validation time so misconfiguration fails loudly rather than producing wrong-decision output.
- **`QDII_PREMIUM_THRESHOLD_PCT`** — module-level `Final[float]` re-export in `src/irc/memo/qdii_premium_lines.py`, bound `= QDII_MAX_PREMIUM_DEFAULT` (NOT a fresh literal). Single locus the memo §5 溢价 column footnote, §6 marker block, §7 hard-block prefix, and `qdii_premium.json::threshold_pct` all read from. ## Macro excerpt rendering

- **Deterministic theme excerpt** — the byte-deterministic prose slice rendered after a theme name in memo §2 `本周宏观研究要点` bullets and in the §3 `IRC_GOLD_EVIDENCE_BEGIN/END` block. Built by `_summary_from_theme_report(report, *, max_chars=400)` in `src/irc/commands/gold_cmd.py`: first strip the `# <theme>` heading + `## Citations` footer via `extract_prose_from_report_md`; then call `_first_prose_paragraph(prose, *, max_chars)` to skip subheadings/bold-only lines and accumulate a paragraph-shaped excerpt; then truncate to `max_chars` with `…` suffix. The result lands in `ThemeReportRef.summary` and flows verbatim through `gold_regime.json["evidence"]` and the memo §2/§3 renderers. Same string is read by both surfaces — no per-surface re-extraction. See [ADR 0008](docs/adr/0008-macro-research-excerpt-depth.md).
- **Macro excerpt depth (skip-rule + paragraph accumulator)** — the two-stage extraction algorithm inside `_first_prose_paragraph`. **Skip rule (a)** drops any line whose `stripped` form (i) starts with `##` (catches `## subheading` AND `### subsubheading` AND deeper — the top-level `# theme` is already stripped by `extract_prose_from_report_md`), or (ii) matches `re.fullmatch(r"\*\*[^*]+\*\*", stripped)` / `re.fullmatch(r"__[^_]+__", stripped)` (bold-only line with NO trailing prose — lines like `**政策优化信号**：…` have trailing prose and DO NOT skip), or (iii) is empty BEFORE any prose line has entered the buffer. **Accumulator rule (b)** locates the first non-skip prose line, strips a leading bullet marker (`- `, `* `, `+ `) if present, and then continues collecting subsequent non-skip lines (bullet markers similarly stripped on each line) until ONE of: (i) `≥3` sentence-ending punctuation marks `{".", "。", "！", "!", "?", "？"}` are present in the buffer, (ii) the joined buffer reaches `≥150` visible characters (excluding leading/trailing whitespace), or (iii) a blank line is encountered AFTER `≥1` prose line is in the buffer (blank lines before the first prose line are skipped, not terminating). Lines joined with a single ASCII space. The hybrid stop-rule guarantees ≥150 chars of substance regardless of report shape (paragraph-shaped vs bullet-list-shaped).
- **Macro excerpt char cap** — `max_chars=400` is the production default (raised from pre-F5 `220`). When the accumulated paragraph exceeds the cap, truncate to `max_chars - 1` and append the single horizontal-ellipsis char `…`. The kwarg-only override is preserved so tests pin behaviour at smaller caps. Worst-case section length: 7 themes × 400 chars / ~50 chars-per-line ≈ ~25 visible lines in §2 (`本周宏观研究要点`); empirically themes hit the 150-char floor far more often than the 400-char ceiling, so typical §2 length is ~10–15 lines. Inline `[N]` citation markers from the theme report's own footnote-numbering are STRIPPED from the excerpt (regex `_LLM_REF_MARKER_RE = r"\s*\[\d+\]\s*"`) before accumulation. The ADR initially preferred to leave them verbatim, but the /ship step 8 silent-failure hunter for F5 (fix commit `997e418`) flagged a visual collision with the memo's downstream `[N]` footnote numerals — a reader cannot distinguish an LLM-internal source index from a genuine footnote reference. The strip is also why a 400-char cap cannot land inside a half-bracket. The strip reversal is documented in [ADR 0008](docs/adr/0008-macro-research-excerpt-depth.md) §1.
- **Theme-excerpt citation_id churn** — because `ThesisEvidence.citation_id` is content-derived (ADR 0001 §2: `canonical_url_or_fallback = url or f"{source}:{date}:{summary[:64]}"`) and theme-report evidence has empty `url`, changing the extracted summary changes the row's citation_id. Expected on the F5 deploy run; not a contract violation (ADR 0001 explicitly states no cross-run id stability — same-content/same-id, different-content/different-id). The two-run byte-equality contract (same `data/research/` snapshot → byte-identical `gold_regime.json` → identical ids) is preserved. Operators reviewing diff-of-runs see macro-theme citation_ids change once and then stabilise. Memo §2/§3 `[ref:...]` markers continue to match `gold_regime.json["evidence"]` ids by construction (the same `evidence_by_source` map renders the markers); the publishable-set lockdown integration test (item 008 AC19) stays green.

## Audit gates and enforcement modes

- **`IRC_CITATION_ENFORCE_MODE`** — env var controlling the citation audit gate at the opportunity and memo stages. Values: `{"off","warn","block"}`. Default: `block` (fail-closed). **Canonical-path override:** when `out_dir.resolve().parent.name == "outputs" AND re.fullmatch(r"\d{4}-\d{2}-\d{2}", out_dir.name)`, the env var is ignored and `block` is forced — the gate is non-negotiable on production output paths. Non-canonical paths (scratch / tmp_path / non-`outputs/` directories) honour the env var verbatim; unknown values fall back to `block` with a stderr warning. The shadow log `outputs/<date>/citation_audit.json` is written in ALL modes (including `block` — written immediately before the `RuntimeError` raise) so the audit trail is observable even when the gate is hard-blocking. Single file, shared across both stages: opportunity-stage writes `opportunity_findings` + `constituent_findings` + `discipline_findings` + empty `memo_findings`; memo-stage RMW-overlays `memo_findings`. See item 009 spec §3 AC11–AC13.
- **Citation gate v1 dimension binding** — v1 enforces a STRUCTURAL dual-leg binding at the row level: every publishable row's `thesis_evidence` must carry ≥1 `citation_kind="data"` entry AND ≥1 `citation_kind="information"` entry, both with `scope in {"instrument","constituent"}` and `owner_instrument_id == row.instrument_id`. The diagnosis-doc D2a per-dimension `type` tagging (`valuation_metric` / `heat_metric` / etc.) and the "drop the dimension's conclusion text from rendered output if uncited" renderer behaviour are **deferred to v2** — they require producer-side changes to `derive_thesis_from_evidence` (5 adapters × 4 dimensions) and a `compose_opportunity_report` renderer surface that knows how to drop dimension-specific text. V1 ships the row-blocking finding shape; v2 will add the dimension-tagging contract and the drop-behaviour renderer. See item 009 spec §5 D1 + §6 Q1, Q5 (both deferred).


## Thesis-news scoring

- **`news_summaries` (scoring input)** — `dict[str, tuple[str, ...]]` passed to `run_scoring`, keyed by `instrument_id`. The tuple holds 0–N **theme report summaries** (`ThemeReport.report_md` strings) that the keyword rubric in `src/irc/scoring/factors/thesis_news.py::score_thesis_news` counts `_POS` / `_NEG` lexicon hits against. Empty tuple → factor returns `score=50.0, components={"data_completeness": 0.0, "neutral_default": 1.0}` (the cold-start invariant). Built by `build_news_summaries(reports, watchlist)` at the `score_cmd.run_score` edge from already-persisted `data/research/` reports; **never** populated via live per-instrument fetch (would violate determinism). Pre-F4 production hit the empty-tuple branch for every row because the call site passed `news_summaries={}`. See [ADR 0007](docs/adr/0007-thesis-news-scoring.md).
- **`themes_for_instrument`** — pure function `themes_for_instrument(asset_class: str) -> tuple[str, ...]` in `src/irc/scoring/news_summaries.py`. Returns a sorted, stable tuple of theme names from the fixed set `{us_monetary, us_fiscal_politics, cn_monetary, cn_equity_property_policy, geopolitics, gold_drivers, holdings_sector}`. Mapping is keyed off the **real seven `asset_class` values** present in `config/universe/*.yaml` (`cn_bond_fund`, `cn_equity_fund`, `cn_etf`, `gold`, `hk_etf`, `qdii_global`, `us_etf`) — NOT the invented `cn_a_broad` / `cn_a_sector` / `qdii_us` / `qdii_hk` labels from the F4 spec's first draft. `market` is **not** part of the signature (`cn_on_exchange` vs `cn_off_exchange` does not change which macro themes are thematically relevant). Unknown `asset_class` values return the empty tuple silently — falls back to neutral 50.0 per the empty-input invariant. Locked by [ADR 0007](docs/adr/0007-thesis-news-scoring.md).
- **Theme→asset-class mapping (locked)** — | `asset_class` | mapped themes (sorted ASC) | rationale | |---|---|---| | `gold` | `(geopolitics, gold_drivers, us_monetary)` | gold reacts to safe-haven flows, real yields, USD | | `cn_equity_fund` | `(cn_equity_property_policy, cn_monetary, holdings_sector)` | CN-A active equity reacts to CN policy + user-held sector flow | | `cn_etf` | `(cn_equity_property_policy, cn_monetary, holdings_sector)` | same equity-flavour as cn_equity_fund | | `cn_bond_fund` | `(cn_monetary,)` | bonds rarely differentiate on news beyond rates | | `hk_etf` | `(cn_equity_property_policy, cn_monetary, geopolitics, holdings_sector)` | HK reacts to CN policy + geopolitics; holdings flow applies | | `us_etf` | `(geopolitics, us_fiscal_politics, us_monetary)` | USD-denominated equity reacts to US macro + geopolitics | | `qdii_global` | `(geopolitics, us_fiscal_politics, us_monetary)` | global QDIIs are predominantly USD equity exposure | | else / unknown | `()` | empty tuple → neutral 50.0 fallback; documented in ADR | Order within the tuple is theme-name ASC so two-run byte equality of `scoring.json` holds.
- **`build_news_summaries`** — pure function `build_news_summaries(reports: dict[str, ThemeReport], watchlist: pd.DataFrame) -> dict[str, tuple[str, ...]]` in `src/irc/scoring/news_summaries.py`. For each watchlist row: calls `themes_for_instrument(row.asset_class)`, looks up each theme in `reports`, and emits `report.report_md` for themes where the report **succeeded** (`failure_reason == "" AND report_md != ""`). Themes with empty/failed reports are skipped silently (an empty-string summary would inflate the tuple count without signal). Output per-instrument tuple is sorted by theme name ASC. No filesystem access inside the function — reports are loaded by the command layer via `load_theme_reports` and passed in.

## Holdings ingest policy

- **`fund_holdings` ingest policy** — wall-clock 30-day staleness gate via `_china_today()` (UTC+8); named-column `INSERT OR REPLACE INTO fund_holdings (...) VALUES (?, ...)` with `executemany` (mirrors `_upsert_prices` / `_upsert_nav` / `_upsert_instruments` precedent — positional `INSERT INTO fund_holdings VALUES (...)` is forbidden in production code so future schema column additions don't silently corrupt data); no-delete-on-empty (`MAX(report_date)` naturally promotes fresh over stale; explicit deletion would create a non-pure side effect and complicate idempotency); no-prune retention (historical quarters accumulate; disk footprint < 1 MB/year). Single source of truth is item 003's `ActiveFundSnapshot` cache for `cn_equity_fund` and (when present) `cn_etf`, with `fetch_cn_etf_holdings` as the AkShare fallback ONLY for `cn_etf` cache-misses. Best-effort enrichment for the scoring layer (`scoring/metrics_loader._latest_holdings_concentration`) — partial failure NEVER blocks `run_ingest` (no `HaltReason`, exit 0 even when 100% of targets fail). Idempotent same-day reruns (fresh table → zero `INSERT` statements). Per-row determinism: rows written in `(weight_pct DESC, holding_ticker ASC)` order so DuckDB rowid is reproducible across two-run rerun. See item 010 spec.
