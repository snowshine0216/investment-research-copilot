# Investment Research Copilot — Domain Glossary

Canonical terms used in the opportunity / memo / discipline pipeline. Pointed to by the diagnosis doc, the workflow diagram, and code reviews. This file is a glossary, not a spec.

## Evidence & citation

- **Active fund** — an actively-managed CN equity fund (`asset_class="cn_equity_fund"`). The disclosed top-N holdings reflect manager judgement, so each holding receives its own evidence record. Subject to the **drill-through requirement**: per-constituent data + information legs (filing/NAV + broker/news).
- **Passive ETF / tracked index** — `asset_class="cn_etf"` or a tracked CN index. The fund is rule-based, so per-constituent qualitative evidence is **not** required. Investability is described at the **fund level**: NAV/return metrics as the data leg, ETF announcement (or `fund_announcement_em`) as the information leg. The "ANALYZE ONE by ONE" mandate does not apply to passive vehicles.
- **Drill-through requirement** — top-N holdings of an **active fund** must each carry their own data + information leg evidence. Does not apply to passive ETFs or tracked indices.
- **Data leg** — quantitative primary evidence (`citation_kind="data"`): filing digest, fund NAV report. Not opinion-derived.
- **Information leg** — narrative or opinion-bearing evidence (`citation_kind="information"`): broker report, news item, fund announcement. Filing-only never satisfies it.
- **Dual-coverage gate** — a publishable opportunity row requires ≥1 data-leg AND ≥1 information-leg citation, both from `scope in {"instrument", "constituent"}` and both with `owner_instrument_id == row.instrument_id`. Macro/policy scope alone never satisfies either leg.
- **Citation scope** — `instrument` (about the fund itself) | `constituent` (about a held stock) | `asset_class_macro` (theme report) | `policy` (regulatory). The first two are gate-satisfying; the latter two are supplemental.
- **Citation ID** — 16-char sha256 of `(owner_instrument_id, scope, constituent_key, type, canonical_url_or_fallback, date)` where `canonical_url_or_fallback` is the URL, or `source:date:summary[:64]` when URL is empty. 64 bits ⇒ collision-resistant (≤2.7e-10 for ≤100k/run) but not collision-proof; the `build_cited_map` duplicate-id detector raises immediately if a collision ever fires. See [ADR 0001](docs/adr/0001-citation-data-model.md).
- **Scope precedence** (for selector tie-breaking and "fill-remaining" slots): `instrument > constituent > asset_class_macro > policy`. The instrument/constituent pair are the only scopes the dual-coverage gate accepts; macro/policy never satisfy the gate but appear in the fill-remaining tail.
- **Citation selector priority** (deterministic; used by the picks table and evidence pool to pick ≤3 citations per instrument): sort key per entry = `(scope_rank, kind_rank, holding_weight_pct, iso_date_recency, citation_id asc)`. The data slot picks the top `kind="data"` entry; the info slot picks the top `kind="information"` entry; remaining slot is filled by the same key minus the kind component. Two shuffled input orders must produce the same 3-entry output.
- **Contributing dimensions** — the subset of `{valuation, heat, thesis, product_quality}` whose sub-state drove the final `opportunity_state`. Derived deterministically from the four sub-states by `derive_contributing_dimensions` (Slice A0); never populated ad-hoc. The dual-coverage gate iterates this set so that each driver of the conclusion is independently cited.

## Active-fund fetch engine

- **`FundHolding`** — one disclosed top-N holding of an active fund: `(symbol, name_cn, weight_pct, exchange, provider_symbol)`. `weight_pct` is in **percent units** (0.0–100.0), NOT a fraction. `exchange` is `SH | SZ | BJ | HK | US | UNKNOWN`; the parser stamps `UNKNOWN` rather than guessing when a ticker cannot be resolved. See [ADR 0002](docs/adr/0002-active-fund-fetch-engine.md) §4.
- **`HoldingsResult`** — return shape of `fetch_cn_etf_holdings`: `(constituents: tuple[FundHolding, ...], source_report_date, source_report_quarter)`. The `source_report_quarter` is **provider-declared** (from the `季度` column, e.g. `"2024Q1"`), NOT calendar quarter.
- **`ConstituentAnalysis`** — per-holding structured evidence: `(symbol, name_cn, weight_pct, evidence: tuple[ThesisEvidence, ...], failure_reasons: tuple[str, ...], one_line_view: str)`. Lives on `OpportunityRow.constituent_analyses` and `DisciplineRow.constituent_analyses`. Every `ThesisEvidence` in `.evidence` carries `scope="constituent"`, `parent_fund_id=fund_id`, `constituent_key=symbol`. The audit gate (item 009) reads structured `.evidence`; `one_line_view` is for human consumption only.
- **`ActiveFundSnapshot`** — full per-fund result: `(fund_id, source_report_date, source_report_quarter, cache_probed_at, constituent_analyses, failure_reasons_by_symbol, fund_level_failure_reasons)`. Distinct from the legacy `ConstituentSnapshot` (which still serves passive ETFs / tracked indices). Cache layout: `data/fundamentals/{source_report_quarter}/active_fund/fund_{iid}.json`. See [ADR 0002](docs/adr/0002-active-fund-fetch-engine.md).
- **Disclosure quarter** — the fiscal quarter the provider attributes a holdings disclosure to (e.g. `2024Q1` for a March-end report). Distinct from **calendar quarter** (when the fetch ran). Cache keys, freshness checks, and audit comparisons always use disclosure quarter.
- **Fail-closed freshness probe** — when a cached `ActiveFundSnapshot` is older than `IRC_CACHE_FRESHNESS_DAYS` (default 7) on a canonical run, fire a probe (`fetch_cn_etf_holdings(provider_symbol, top_n=1)`). Probe failure (exception or empty) forces a full refetch — never silently reuses stale data. Probe succeeding with the same quarter advances `cache_probed_at` and reuses the body. See [ADR 0002](docs/adr/0002-active-fund-fetch-engine.md) §2.
- **Preflight fetch budget** — `IRC_FETCH_BUDGET` (default 2000) caps total AkShare calls per run. Computed at `_build_rows` entry BEFORE any per-instrument fetch; a single hard gate, no mid-loop checks. Plan-hash-keyed resumable state file (`data/fundamentals/.fetch_state_<hash>.json`) lets interrupted runs resume.
- **Forbidden adapter pair** — for a given `FundHolding.exchange`, certain adapters MUST NOT be called (e.g. `fetch_cn_broker_reports` for HK constituents). Misrouting returns nonsense data without a provider error. Enforced by the dispatcher's branch structure and locked by tests. See [ADR 0002](docs/adr/0002-active-fund-fetch-engine.md) §4.

## Test infrastructure

- **Live test gate** — paired `(pytest marker, env var)` mechanism for tests that hit real upstreams (AkShare, LLM providers, etc.). The marker (`live_akshare`, `live_llm`, …) lets a developer select the tests via `pytest -m <marker>`; the env var (`IRC_RUN_LIVE_AKSHARE=1`, etc.) is a separate switch a developer must opt into. Both must be active for the test to run; the module-level `pytest.mark.skipif(not _RUN, …)` is what enforces the env-var gate. Default `pytest` invocations skip every live test silently. Pattern lives at `tests/integration/test_live_endpoints.py` (the historical `RUN_LIVE_INGEST_TESTS` family) and the new `tests/fundamentals/test_fund_announcement_em_live.py` (the canonical `IRC_*`-prefixed family that future live-test additions follow).
- **Q4 prerequisite** — the load-bearing assumption that `ak.fund_announcement_em(symbol=<fund_id>)` exists, is callable, and returns a non-empty time-bound DataFrame for gold (`518880`), bond (`000001`), and an active CN equity fund (`005827` sanity check). Failing this gate makes the `citation_kind="information"` leg impossible for gold + cn_bond_fund, so every such opportunity row would fail the dual-coverage gate. Verified by `tests/fundamentals/test_fund_announcement_em_live.py::test_fund_announcement_em_q4_gate`. On FAIL, the autodev orchestrator STOPS the run before item 005 and surfaces the structured `Q4 PREREQUISITE FAILURE` message; see `docs/diagnosis-thesis-cards-evidence-gap.md` §5 Open Q4 for the fall-back options (b: theme-report scope promotion, c: exclude gold + cn_bond_fund from V1).
- **AkShare fixture** — a JSON-serialised shadow of a live AkShare DataFrame, written to `tests/fixtures/akshare/<fn_name>_<symbol>.json` after a successful live run. Format: `{"columns": [...], "rows": [...], "captured_at": "<ISO-8601 UTC>", "akshare_version": "<version>"}` with Chinese column names preserved verbatim (UTF-8 JSON, `ensure_ascii=False`). The fixture is **always overwritten** on every successful live run — it is a captured shadow, not a frozen snapshot. Downstream mocked unit tests load it to assert column-name handling matches the real shape. Tests never assert content equality against the fixture (only column shape + non-empty), so daily content drift is benign.
- **Column equivalence map** — a `dict[logical_name, tuple[candidate_columns, ...]]` that resolves AkShare's Chinese (or alternate) column headers to the four logical names the gate cares about: `title`, `type`, `date`, `url`. Tolerates known synonyms (e.g. `公告时间` ↔ `公告日期`). A REMOVED required column raises a structured `Q4 PREREQUISITE FAILURE` listing the candidates and observed columns; ADDED bonus columns are silently ignored (only the 4 gate-relevant columns are checked). The map is the contract surface for AkShare schema drift.
