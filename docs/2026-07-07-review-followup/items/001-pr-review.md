- src/irc/notify/health.py:126-129 (`_signal_items`) / src/irc/commands/notify_health.py (`_compute_flow_capture_health`'s `radar.get("board_states", [])`) — nit (test-coverage + docstring-accuracy gap, not a live/user-facing bug) — the module docstring claims "Every builder is TOTAL... never an exception," and `tests/notify/test_health.py` has four dedicated regression tests for exactly this class of bug (`funds:"x"`, `board_pe_freshness:12345`, non-dict fund record, `macro_snapshots:null` — all traced to "proven live crash" in code comments). A fifth sibling shape was missed: a *valid* dict fund record whose `signal` key is JSON `null` (e.g. `{"signal": None, "published_state": "ok"}`) reaches `rec.get("signal", {}).get("status")`; since `dict.get(key, default)` only substitutes the default when the key is *absent* (the exact P0 pattern this PR's own `_weekly_shape_ok` guard was written to avoid), `.get("status")` is called on `None` and raises `AttributeError`. Reproduced directly against the PR branch:
  ```
  >>> monitor_health({"board_pe_freshness": {...}, "funds": {"f1": {"signal": None, "published_state": "ok"}}}, {}, tdays)
  AttributeError: 'NoneType' object has no attribute 'get'
  ```
  Same unguarded-`.get`-on-possibly-null pattern exists for `board_states` in `_compute_flow_capture_health`. **Not a production risk**: both call sites are reached only through the edge-level `_safe_health` / `read_flow_capture` try/except nets, which are explicitly designed to catch "a future shape bug the isinstance guards ... don't yet cover" (P0-1b, `notify_health.py:29-39`) and degrade to `health_unknown` — verified end-to-end (constructed the same fixture through `read_monitor_health` against a temp `outputs/` tree: logs a warning, returns `HealthDigest` with two `health_unknown` items, no exception propagates). So the notifier cannot crash on this input. The gap is that the *pure* builder's "total" claim is false for this shape, and unlike its four siblings it has no regression test — worth a follow-up `_funds_shape_ok` tightening (validate `rec.get("signal")` is a dict when present) + a `test_monitor_health_null_signal_is_health_unknown`-style test, consistent with the PR's own established fix pattern.
