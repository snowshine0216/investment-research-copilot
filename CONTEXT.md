# Investment Research Copilot — Domain Glossary

Canonical terms used in the opportunity / memo / discipline pipeline. Pointed to by the diagnosis doc, the workflow diagram, and code reviews. This file is a glossary, not a spec.

## Evidence & citation

- **Active fund** — an actively-managed CN equity fund (`asset_class="cn_equity_fund"`). The disclosed top-N holdings reflect manager judgement, so each holding receives its own evidence record. Subject to the **drill-through requirement**: per-constituent data + information legs (filing/NAV + broker/news).
- **Passive ETF / tracked index** — `asset_class="cn_etf"` or a tracked CN index. The fund is rule-based, so per-constituent qualitative evidence is **not** required. Investability is described at the **fund level**: NAV/return metrics as the data leg, ETF announcement (or `fund_announcement_em`) as the information leg. The "ANALYZE ONE by ONE" mandate does not apply to passive vehicles.
- **Drill-through requirement** — top-N holdings of an **active fund** must each carry their own data + information leg evidence. Does not apply to passive ETFs or tracked indices.
- **Data leg** — quantitative primary evidence (`citation_kind="data"`): filing digest, fund NAV report. Not opinion-derived.
- **Information leg** — narrative or opinion-bearing evidence (`citation_kind="information"`): broker report, news item, fund announcement. Filing-only never satisfies it.
- **Dual-coverage gate** — a publishable opportunity row requires ≥1 data-leg AND ≥1 information-leg citation, both from `scope in {"instrument", "constituent"}` and both with `owner_instrument_id == row.instrument_id`. Macro/policy scope alone never satisfies either leg.
- **Citation scope** — `instrument` (about the fund itself) | `constituent` (about a held stock) | `asset_class_macro` (theme report) | `policy` (regulatory). The first two are gate-satisfying; the latter two are supplemental.
- **Citation ID** — 16-char sha256 of `(owner_instrument_id, scope, constituent_key, type, canonical_url_or_fallback, date)` where `canonical_url_or_fallback` is the URL, or `source:date:summary[:64]` when URL is empty. 64 bits ⇒ collision-resistant (≤2.7e-10 for ≤100k/run) but not collision-proof; the `build_cited_map` duplicate-id detector raises immediately if a collision ever fires. See [ADR 0001](docs/adr/0001-citation-data-model.md).
- **Scope precedence** (for selector tie-breaking and "fill-remaining" slots): `instrument > constituent > asset_class_macro > policy`. The instrument/constituent pair are the only scopes the dual-coverage gate accepts; macro/policy never satisfy the gate but appear in the fill-remaining tail.
- **Citation selector priority** (deterministic; used by the picks table and evidence pool to pick ≤3 citations per instrument): sort key per entry = `(scope_rank, kind_rank, holding_weight_pct, iso_date_recency, citation_id asc)`. The data slot picks the top `kind="data"` entry; the info slot picks the top `kind="information"` entry; remaining slot is filled by the same key minus the kind component. Two shuffled input orders must produce the same 3-entry output.
- **Contributing dimensions** — the subset of `{valuation, heat, thesis, product_quality}` whose sub-state drove the final `opportunity_state`. Derived deterministically from the four sub-states by `derive_contributing_dimensions` (Slice A0); never populated ad-hoc. The dual-coverage gate iterates this set so that each driver of the conclusion is independently cited.

## Active-fund fetch engine

- **`FundHolding`** — one disclosed top-N holding of an active fund: `(symbol, name_cn, weight_pct, exchange, provider_symbol)`. `weight_pct` is in **percent units** (0.0–100.0), NOT a fraction. `exchange` is `SH | SZ | BJ | HK | US | UNKNOWN`; the parser stamps `UNKNOWN` rather than guessing when a ticker cannot be resolved. See [ADR 0002](docs/adr/0002-active-fund-fetch-engine.md) §4.
- **`HoldingsResult`** — return shape of `fetch_cn_etf_holdings`: `(constituents: tuple[FundHolding, ...], source_report_date, source_report_quarter)`. The `source_report_quarter` is **provider-declared** (from the `季度` column, e.g. `"2024Q1"`), NOT calendar quarter.
- **`ConstituentAnalysis`** — per-holding structured evidence: `(symbol, name_cn, weight_pct, evidence: tuple[ThesisEvidence, ...], failure_reasons: tuple[str, ...], one_line_view: str)`. Lives on `OpportunityRow.constituent_analyses` and `DisciplineRow.constituent_analyses`. Every `ThesisEvidence` in `.evidence` carries `scope="constituent"`, `parent_fund_id=fund_id`, `constituent_key=symbol`. The audit gate (item 009) reads structured `.evidence`; `one_line_view` is for human consumption only.
- **`ActiveFundSnapshot`** — full per-fund result: `(fund_id, source_report_date, source_report_quarter, cache_probed_at, constituent_analyses, failure_reasons_by_symbol, fund_level_failure_reasons, fund_level_evidence)`. Distinct from the legacy `ConstituentSnapshot` (which still serves passive ETFs / tracked indices). Cache layout: `data/fundamentals/{source_report_quarter}/active_fund/fund_{iid}.json`. See [ADR 0002](docs/adr/0002-active-fund-fetch-engine.md).
- **`ActiveFundSnapshot.fund_level_evidence`** — `tuple[ThesisEvidence, ...]` (default `()`) carrying fund-level NAV (`citation_kind="data"`, `scope="instrument"`, `owner_instrument_id=fund_id`) and announcement (`citation_kind="information"`, same scope/owner) records, fetched unconditionally by `_build_active_fund_snapshot` via the same `fetch_fund_nav_report` + `fetch_fund_announcements` adapters used by `_build_fund_level_snapshot`. Deliberately named DIFFERENTLY from `FundLevelSnapshot.evidence` so the cache serialiser can't conflate the two. Consumed by Policy B rule 2.5 (foreign-heavy short-circuit). Older cache files missing the field re-hydrate with `()` — graceful migration, no manual cache invalidation. See [ADR 0003](docs/adr/0003-failure-mode-policy-b.md) §7.
- **Disclosure quarter** — the fiscal quarter the provider attributes a holdings disclosure to (e.g. `2024Q1` for a March-end report). Distinct from **calendar quarter** (when the fetch ran). Cache keys, freshness checks, and audit comparisons always use disclosure quarter.
- **Fail-closed freshness probe** — when a cached `ActiveFundSnapshot` is older than `IRC_CACHE_FRESHNESS_DAYS` (default 7) on a canonical run, fire a probe (`fetch_cn_etf_holdings(provider_symbol, top_n=1)`). Probe failure (exception or empty) forces a full refetch — never silently reuses stale data. Probe succeeding with the same quarter advances `cache_probed_at` and reuses the body. See [ADR 0002](docs/adr/0002-active-fund-fetch-engine.md) §2.
- **Preflight fetch budget** — `IRC_FETCH_BUDGET` (default 2000) caps total AkShare calls per run. Computed at `_build_rows` entry BEFORE any per-instrument fetch; a single hard gate, no mid-loop checks. Plan-hash-keyed resumable state file (`data/fundamentals/.fetch_state_<hash>.json`) lets interrupted runs resume.
- **Forbidden adapter pair** — for a given `FundHolding.exchange`, certain adapters MUST NOT be called (e.g. `fetch_cn_broker_reports` for HK constituents). Misrouting returns nonsense data without a provider error. Enforced by the dispatcher's branch structure and locked by tests. See [ADR 0002](docs/adr/0002-active-fund-fetch-engine.md) §4.

## Fund-level fetch engine

- **`FundNavReport`** — fund-level NAV time series snapshot: `(fund_id, fund_name, latest_nav, latest_nav_date, nav_history, source_report_quarter)`. `latest_nav_date` is ISO 8601 `str` (converted from AkShare's `datetime.date` at the adapter boundary). `source_report_quarter` is derived from `latest_nav_date` via `infer_quarter` (calendar-quarter rule reused from ADR 0002 §1 for NAV, since NAV is a daily series with no provider-declared disclosure quarter). The data-leg of the dual-coverage gate for gold / cn_bond_fund / cn_etf / tracked CN ETF rows.
- **`FundAnnouncement`** — one fund-specific announcement record: `(fund_id, title, topic, date, report_id)`. `topic` is `Literal["dividend", "report", "personnel"]` — the endpoint origin. `date` is ISO 8601 `str` (normalised from AkShare's `datetime.date`). `report_id` is the opaque `报告ID` provider reference; there is **no URL column** in AkShare 1.18.63's topic-specific announcement endpoints, so `ThesisEvidence.url=""` and the citation-id preimage falls back to `summary[:64]` (per ADR 0001 §2), with `summary = f"[{report_id}] {title}"` to make the discriminator participate in the hash.
- **`FundLevelSnapshot`** — full per-fund result for **non-active** V1 asset classes: `(fund_id, nav_report, announcements, evidence, source_report_quarter, cache_probed_at, fund_level_failure_reasons, evidence_gaps)`. Distinct from `ActiveFundSnapshot` (which has per-constituent analyses) and `ConstituentSnapshot` (legacy display-only). `nav_report` is `None` when NAV fetch failed or for the QDII sentinel. Cache layout: `data/fundamentals/{source_report_quarter}/nav/fund_{fund_id}.json` — parallel to `active_fund/` per ADR 0002 §5.
- **NAV-derived quarter (latest-`nav/` probe)** — fund-level `FundLevelSnapshot.source_report_quarter` is derived from `FundNavReport.latest_nav_date` via `infer_quarter` (calendar-quarter rule, ADR 0002 §5) and is therefore **unknowable before the fetch**. Its cache-presence / idempotence probe is consequently a **latest-`nav/`-quarter scan** (`root/fundamentals/*/nav/fund_{id}.json`, most-recent quarter — `_load_latest_nav_cached`), shared by both the writer-side autobuild gate and the reader-side load so probe and consumer always agree on the same quarter. This is the deliberate difference from the **active-fund** snapshot, which is keyed by the **provider-declared holdings quarter** (`HoldingsResult.source_report_quarter`) and is probed at the resolved analyze-context quarter (item 001). A fixed analyze-context-quarter probe for a fund-level snapshot would write quarter X (NAV-derived) yet read quarter Y → non-idempotent; the latest-`nav/` scan avoids that.
- **Fund-level dispatch** — `build_snapshot` routes by `LookthroughTarget.kind`: `active_fund` → `_build_active_fund_snapshot` (item 003); `qdii_us`/`qdii_hk`/`qdii_global` → `_build_qdii_sentinel_snapshot` (in-process, zero-fetch); `gold`/`bond`/`broad_index`/`sector_theme` with non-empty `provider_symbol` → `_build_fund_level_snapshot`; else legacy display-only `_build_legacy_snapshot`. The dispatch keys off `target.kind` only — never `target.key` or `target.display_cn`. See [ADR 0002](docs/adr/0002-active-fund-fetch-engine.md) §5.
- **QDII V1 exclusion** — every `qdii_us`/`qdii_hk`/`qdii_global` `LookthroughTarget` produces a sentinel `FundLevelSnapshot` with `nav_report=None, announcements=(), evidence=(), evidence_gaps=("qdii_information_unavailable",)`. Zero AkShare calls fired. The sentinel is **NOT cached on disk** (gap-only rows have nothing to cache; in-process re-emission is cheaper than I/O). Item 006's H3 universal-gap invariant routes these rows to the discipline failure section only.
- **Static-profile invariant** — the `ak.fund_open_fund_info_em(symbol, indicator="基金概况")` indicator is **NEVER** consulted by the production engine. Fund profile text is static metadata, not a time-bound communication; if it satisfied `citation_kind="information"` it would silently bypass the freshness intent of the information leg. The invariant is enforced **upstream at the adapter layer** — `fetch_fund_nav_report` only calls `indicator="单位净值走势"` and the information leg only emits via `fetch_fund_announcements`. No downstream gate enforcement is required (or possible — `ThesisEvidence` carries no `indicator` field). Locked by an acceptance test that greps for `"基金概况"` in production code.

## Failure-mode + audit policy

- **`failure_reasons` (adapter-level)** — per-constituent diagnostic strings emitted by item 003's adapters when a fetch raised or returned empty (e.g. `"filing_fetch_failed:600519:ConnectionError"`, `"broker_empty:00700"`). Lives on `ConstituentAnalysis.failure_reasons` and on `ActiveFundSnapshot.failure_reasons_by_symbol`. Semantic: "the adapter ran but couldn't produce evidence." Item 006's Policy B reads these to distinguish rule-3 (no data leg) from rule-5 (mixed evidence + failure_reasons) cases.
- **`evidence_gaps` (row-level)** — fund-row-level gap codes on `OpportunityRow.evidence_gaps` (and mirrored on `FundLevelSnapshot.evidence_gaps`). Stamped by items 003 (structural gaps), 005 (QDII sentinel, fund-level failures), and 006 (Policy B). Semantic: "the fund as a whole cannot publish." H3 (item 006) routes any row with non-empty `evidence_gaps` away from `thesis_cards.yaml` + `opportunity_report.json.rows` and into the discipline failure section. Distinct from `failure_reasons` (which is per-constituent diagnostic), `audit_errors` (per-constituent shape-corruption), and `advisory_gaps` (row-level non-blocking advisories). Codes that should warn the operator without blocking publication go into `advisory_gaps`, NEVER `evidence_gaps`.
- **`audit_errors` (per-constituent shape-corruption)** — `tuple[str, ...]` field on `ConstituentAnalysis` (default `()`). Populated by item 006's Policy B when a constituent has BOTH `evidence==() AND failure_reasons==()` — item 003's adapter contract was violated (the constituent was emitted with no evidence and no diagnostic). Format: `"missing_constituent_record:{symbol}"`. Distinct from `failure_reasons` (adapter ran but no evidence) and `evidence_gaps` (row-level disposition). Item 009's `find_incomplete_constituent_analyses` raises on the same predicate as defence-in-depth. The original cached `ConstituentAnalysis` JSON is never mutated — Policy B derives the audit error on evaluation and stamps it on a fresh `ConstituentCoverageEntry` for the rejection record.
- **`advisory_gaps` (row-level non-blocking)** — `tuple[str, ...]` field on `OpportunityRow` (default `()`). Semantic: "evidence quality concern the operator should see, but the row is still publishable." Distinct from `evidence_gaps` (row-blocking; H3 routes to gapped_rows), `expected_omissions` (structural non-features by design — e.g. `constituent_not_applicable`), and `failure_reasons` (per-constituent adapter-level diagnostics). H3 partition predicate is unchanged: `evidence_gaps == ()` alone decides publishability; `advisory_gaps` is orthogonal and carried through into publishable outputs. Codes live in module-level `ADVISORY_GAP_CODES: frozenset[str]` in `src/irc/opportunity/states.py`; `_partition_gaps` becomes a 3-way split returning `(real_gaps, expected_omissions, advisory_gaps)`. May coexist with Policy B rule 2.5 acceptance — e.g. a foreign-heavy active fund can be publishable via rule 2.5 AND carry `top_holdings_broker_thin` simultaneously; both are correct. **Boundary:** `advisory_gaps` describe *current row-level evidence quality*. A *run-level ingest operational event* — e.g. a legulegu throttle suspending the broad-index sweep (`LeguleguCooldownExhausted`) — is **NOT** an advisory_gap: it is logged at ingest (and, future, recorded in a run-level ingest diagnostic artifact), never stamped on a row. Stamping it would mis-attribute cause — an ungrounded row may be uncached, immature, unsupported, OR throttled, and the opportunity stage cannot honestly distinguish these. See [ADR 0005](docs/adr/0005-advisory-gaps-field.md).
- **`top_holdings_broker_thin`** — `advisory_gaps` code emitted by `derive_thesis_from_evidence`'s `ActiveFundSnapshot` branch when an active fund's top-5 holdings have weak broker coverage: `count_broker_empty_top5 >= 2` OR `weight_broker_empty_top5 >= 20.0` (percent units, disjunctive). "Top-5" is the weight-rank prefix with boundary-tie extension mirroring `MATERIAL_HOLDING_QUORUM` precedent. Counted symbols are those whose `failure_reasons` contains an entry matching `broker_empty:*`. Constants `TOP_HOLDINGS_BROKER_THIN_COUNT_THRESHOLD = 2` and `TOP_HOLDINGS_BROKER_THIN_WEIGHT_PCT_THRESHOLD = 20.0` are module-level `Final` (hardcoded by design, same precedent as `FOREIGN_HEAVY_THRESHOLD`). Active-fund only — never emitted for `FundLevelSnapshot` (passive ETF / gold / bond / QDII sentinel) because passive vehicles have no per-constituent broker fetch path. Companion to `missing_broker_coverage` (legacy `ConstituentSnapshot` blocking gap); `top_holdings_broker_thin` is advisory, not blocking.
- **Commodity-cyclical NAV-anchor exclusion** — for a commodity-cyclical theme (`COMMODITY_CYCLICAL_THEMES = frozenset({"metals"})`, `src/irc/opportunity/states.py`), when **no fundamental anchor exists** (`valuation_percentile_fundamental is None`), the NAV self-history percentile is **not** a valuation anchor — it is price momentum. `classify_valuation` withholds **every** directional verdict — `cheap` *and* `expensive`/`very_expensive` alike — and returns the existing `evidence_insufficient` `ValuationState` **before** any band assignment. The exclusion is **symmetric on purpose**: a metals fund reading `cheap` off a post-crash NAV trough is exactly as much a momentum artifact as one reading `very_expensive` at the peak. A future change narrowing the guard to "reject only the expensive end" re-admits momentum-as-valuation on the cheap side and is a **regression**, not a refinement. Scope: bound to `theme == "metals"`, and `_EQUITY_ASSET_CLASSES` includes `qdii_global`, so the guard covers all metals-themed equity rows (20 `cn_equity_fund` + 1 `qdii_global`, e.g. 378546). A metals fund that later gains a PE anchor (`valuation_percentile_fundamental is not None`) skips the guard and uses the PE rule. The PE anchor accumulates forward via the csindex sector leg (`fetch_cn_sector_index_valuation_history` reading the canonical `市盈率1` PE-TTM column; second best-effort `ingest_index_valuation_history` leg over `_SECTOR_INDEX_KEYS`) and the §3 min-history gate (`MIN_PE_POINTS=120` non-null PE points AND `MIN_PE_DAYS=180` span in `_index_valuation_metrics`). Narrative `_state_drivers` surfaces a withheld valuation as a **non-blocking** mild risk driver (`("valuation_state", "valuation withheld — no fundamental anchor", 1)`) — no `evidence_gap` is added, so H3 publishability is unaffected. Locked by `tests/opportunity/test_states.py` (the symmetric low-NAV + high-NAV + `qdii_global` cross-asset-class invariant tests).
- **`valuation_price_fundamental_divergence`** — `advisory_gaps` code (valuation-grounding item 001 Phase 1) emitted when the **fundamental** index PE-TTM percentile (`valuation_percentile_fundamental`) and the **price/NAV** self-history percentile (`valuation_percentile_self`) disagree. Single pure detector `valuation_divergence_code(inp) -> str | None` (`src/irc/opportunity/states.py`) is the **one source of truth** (R2): it fires when the two percentiles fall in **different band tiers** (`_band(f) != _band(n)`, sharing `_VALUATION_BANDS` with `classify_valuation`) **OR** `|f − n| ≥ DIVERGENCE_PCT_GAP` (`0.25`); returns `None` if either percentile is `None`. Registered in `ADVISORY_GAP_CODES` (`opportunity/advisory_gaps.py`), so `_partition_gaps` routes it to `advisory_gaps`, **NEVER** `evidence_gaps` — the row stays publishable, H3 partition and SAME-3 are untouched. `classify_valuation` uses the detector only for a **reason note** (price-near-highs-but-PE-low ⇒ earnings outran price ⇒ not really expensive, and the reverse as a warning; its signature stays `(state, reason)`); `build_opportunity_row` folds the code into `combined_gaps` via `_divergence_gaps` (a 0/1-tuple wrapper) **before** `_partition_gaps`. Surfaced on each discipline-report row as the inline advisory suffix `证据缺口：价格与基本面估值背离` (`opportunity/report.py`), co-existing with other advisory notes (e.g. `核心持仓券商覆盖不足`). Mirrors `top_holdings_broker_thin`'s advisory-not-blocking posture. See [ADR 0005](docs/adr/0005-advisory-gaps-field.md).
- **`MATERIAL_HOLDING_QUORUM`** — the formula `ceil(top_N / 2)` used by Policy B to determine the material top-half of a fund's holdings ranked by `weight_pct` descending. For `top_n=10` the material set has 5 holdings, EXTENDED to include any holding whose `weight_pct` equals the cutoff weight (tied at the boundary). Exposed as a module-level `Callable[[int], int]` from `src/irc/opportunity/rejection_log.py` so future asset classes can swap the formula.
- **Material top-half** — the `MATERIAL_HOLDING_QUORUM`-sized subset of an active fund's holdings, ranked by weight descending with boundary-tie extension. Each holding in the material set must satisfy the info-leg requirement; tail holdings (weight rank > material size) are data-only-permitted. The set is the gate for Policy B rule 4.
- **Policy B (weight-aware quorum)** — the audit policy that decides whether an `ActiveFundSnapshot` is publishable. Pure function `evaluate_policy_b(snapshot, *, top_n)` in `src/irc/opportunity/policy_b.py` returns a `PolicyBVerdict` carrying `gap_codes`, `audit_errors`, `decision_rule`, `material_symbols`, and `constituent_coverage`. Applies ONLY to `ActiveFundSnapshot` — `FundLevelSnapshot` (gold/bond/cn_etf/QDII-with-provider_symbol) and `ConstituentSnapshot` (legacy display-only) do not have per-constituent evidence and are evaluated at the fund-level only. **Six rules** in fixed precedence: (1) holdings_fetch_failed, (2) missing_constituent_record audit error, (2.5) foreign-heavy short-circuit (rule 2.5; see entry below), (3) per-holding data leg required for ALL top-N, (4) per-holding info leg required for material top-half, (5) incomplete_constituent_coverage. See [ADR 0003](docs/adr/0003-failure-mode-policy-b.md) §1 + §7.
- **Foreign-heavy fund (rule 2.5 short-circuit)** — an `active_fund` whose top-N constituents are weight-majority listed outside Mainland China (`exchange in {"HK", "US"}`) at share ≥ `FOREIGN_HEAVY_THRESHOLD` (0.50). Policy B rule 2.5 short-circuits such funds by accepting `ActiveFundSnapshot.fund_level_evidence` (NAV data leg + announcement information leg, both `scope="instrument"`, `owner_instrument_id=fund_id`) as the dual-coverage gate substitute for per-holding filings — because the per-holding CN filing pipeline does not reach HK/US tickers and the fund itself is a publishable CN-registered vehicle. Mirrors the 2026-05-25 QDII fetch reform's evidence shape; differs from QDII by keeping the row on the `ActiveFundSnapshot` path so the `## 持仓明细` appendix still renders per-constituent context. When `fund_level_evidence` is empty, rule 2.5 emits gap code `foreign_heavy_fund_level_evidence_missing`. Foreign share is **derived at evaluation time** by `_compute_foreign_listed_share(ranked)`, never persisted on the snapshot (mirrors the "audit_errors derived, never persisted" principle from ADR 0003 §2). `UNKNOWN` and `BJ` exchanges are NOT counted as foreign. **Rule-2.5 funds are exempt from the item-009 per-constituent pure-failure gate** (`find_incomplete_constituent_analyses`): rule 2.5 publishes on fund-level evidence and short-circuits rules 3/4/5, so a foreign constituent whose CN filings pipeline is structurally unreachable is a *legitimate* pure-failure on a publishable row — NOT the gap-stamp escape that gate catches. The opportunity-stage caller passes `foreign_heavy_exempt_ids` (iids where `fired_rule=="2.5" AND gap_codes==()`) and the auditor skips those rows wholesale; the failed constituent still renders as `❌` in the `## 持仓明细` appendix. See [ADR 0003](docs/adr/0003-failure-mode-policy-b.md) §7.
- **`FOREIGN_HEAVY_THRESHOLD`** — module-level constant `= 0.50` in `src/irc/opportunity/policy_b.py`. Comparison is `>=` so a fund sitting exactly at 50.0 % foreign weight is accepted. Hardcoded by design (no YAML / env-var knob in V1): operators tuning thresholds at runtime would silently weaken the audit trail. Future promotion to env var `IRC_FOREIGN_HEAVY_THRESHOLD` follows the same pattern as `IRC_CACHE_FRESHNESS_DAYS` without an API change. Companion to `MATERIAL_HOLDING_QUORUM`.
- **`PolicyBVerdict`** — frozen dataclass returned by `evaluate_policy_b`. Stashed in a `pending_verdicts: dict[str, PolicyBVerdict]` accumulator threaded from `_build_rows` to `_write_opportunity_outputs` so the rejection record can be emitted with full verdict context (decision_rule + material_symbols + constituent_coverage) without re-evaluating Policy B. NEVER mutates `OpportunityRow.thesis_state` — that literal is exclusively set by `derive_thesis_from_evidence`.
- **`RejectionRecord`** — frozen dataclass; one entry per excluded fund. Carries `instrument_id`, `name_cn`, `asset_class`, `rejection_reason` (a `Literal` typed `RejectionReasonCode`), `decision_rule` (human-readable, template-format-locked), `rejection_at_stage`, `constituent_coverage: tuple[ConstituentCoverageEntry, ...]` (weight-ranked breakdown with per-constituent `has_data_leg`/`has_info_leg`/`audit_errors`), `fund_level_failure_reasons`, `fetch_types_attempted`, and `evidence_gaps`. Lives in `src/irc/opportunity/rejection_log.py`.
- **Rejection log (`rejections.json`)** — canonical audit trail at `outputs/{date}/rejections.json`. JSON-serialised `RejectionsDocument` (`run_date`, `plan_hash`, `entries: tuple[RejectionRecord, ...]` sorted by `(asset_class, instrument_id)` ascending). Built in-memory and **written atomically once** at the end of `_write_opportunity_outputs` Step 4 via the existing `.tmp.{pid} → os.replace` pattern — NEVER appended per-row (atomic write-at-end is the project convention; partial files are not a tolerated visible state). Empty rejections case writes `entries: []` (the empty file is the signal of "no rejections this run", not a skip).
- **H3 universal gapped-row invariant** — `_write_opportunity_outputs` partitions `kept_rows` into `publishable_rows` (`evidence_gaps == ()`) vs `gapped_rows` (`evidence_gaps != ()`) at the top of the function, after a fatal pre-gate raise on `fetch_budget_exhausted`. `thesis_cards.yaml` and `opportunity_report.json` emit publishable rows only. The discipline_report.md failure section reads only `instrument_id`, `name_cn`, `evidence_gaps`, `fetch_types_attempted` (4 fields) — never `opportunity_state`/`dca`/`risk`/`note_cn`/`thesis_state` etc., because gapped rows have not earned conclusions. The renderer's signature is the enforcement mechanism. The predicate is `evidence_gaps == ()` ONLY — `advisory_gaps` and `expected_omissions` do NOT participate in the partition (advisory codes are visible on publishable rows by design).
- **`fetch_budget_exhausted` (run-level fatal sentinel)** — gap code that may appear in `evidence_gaps` ONLY transiently inside a buggy code path. Item 003's preflight `FetchBudgetExceeded` raises BEFORE `_build_rows` returns (so production-path rows never carry it). Item 006's H3 Step 1 defence-in-depth check raises `RuntimeError` (a distinct exception class from `FetchBudgetExceeded`) the moment a row carrying this code reaches `_write_opportunity_outputs`. Unlike all other gap codes, this one MUST NOT survive into `rejections.json` — its emission is itself a programming error.
- **V1 systematic exclusions** — a once-per-run `## V1 systematic exclusions: N funds excluded due to US-heavy material holdings` line in `discipline_report.md`, emitted UNCONDITIONALLY (zero-count case still renders with N=0 for greppable stability). ## QDII premium-to-NAV

- **QDII premium-to-NAV ratio** — for an on-exchange QDII feeder ETF (`asset_class ∈ {"us_etf","hk_etf","qdii_global"}` AND `market == "cn_on_exchange"`), the **signed** ratio `(secondary_market_price - NAV) / NAV` derived from AkShare's `fund_etf_spot_em()` bulk table via `premium = -(基金折价率)/100.0`. Positive = trading **above** NAV (premium); negative = trading **below** NAV (discount). Sign convention is flipped from AkShare's native `基金折价率` column (which is discount-positive — confirmed by the 3-row 2026-05-26 sample where `513650: 基金折价率=-2.92` represents a 2.92% premium). Stored on the score dict as `qdii_premium_pct` in ratio units (e.g. `0.0292` for 2.92%), NOT percent units. Off-exchange feeders transact at NAV by construction (see "off-exchange synthetic-zero premium policy") and are stamped with the synthetic value `0.0` rather than fetched.
- **`fetch_qdii_premium_pct`** — `src/irc/data/akshare_client.py::fetch_qdii_premium_pct(symbol: str) -> float | None`. The only effectful entry point for premium values. Returns a signed ratio (per "QDII premium-to-NAV ratio") on success, `None` on AkShare exception / empty table / missing required columns (`代码`, `基金折价率`) / symbol-not-in-table (degrade-to-None contract from ADR 0002 §5). Dispatches through `_fetch_full_etf_spot_table()` which is `lru_cache(maxsize=1)`-decorated so all QDII symbols in a single `irc run` share ONE AkShare call. Tests must call `_fetch_full_etf_spot_table.cache_clear()` in teardown to prevent fixture leakage between tests (same pattern as `_fetch_full_fund_table` / `_fetch_full_etf_table` / `_fetch_full_fund_rank_table`).
- **Off-exchange synthetic-zero premium policy** — when `asset_class ∈ {"us_etf","hk_etf","qdii_global"}` AND `market == "cn_off_exchange"`, the scoring pass stamps `qdii_premium_pct = 0.0` WITHOUT invoking `fetch_qdii_premium_pct`. Off-exchange QDII feeders (open-ended LOF / FOF units) transact at NAV by construction — subscription/redemption settle at end-of-day NAV, so the secondary-market premium concept does not apply. `None` would falsely fire `qdii_premium_unknown` and re-block these structurally-NAV-tracking funds; `0.0` correctly clears both `qdii_premium_unknown` (value is known) and `qdii_premium_too_high` (`0.0 ≤ threshold`). Implemented by `src/irc/scoring/qdii_premium.py::qdii_premium_for_row` as a routing helper that returns `0.0` before calling the fetcher.
- **`qdii_premium_too_high`** — gate-blocking reason code emitted by `compute_blocking_reasons` in `src/irc/decision/gates.py` when `asset_class ∈ {"us_etf","hk_etf","qdii_global"}` AND `score.get("qdii_premium_pct") is not None` AND `qdii_premium_pct > qdii_max_premium_pct` AND `score_action ∈ {"buy_candidate","strong_buy_candidate"}`. Peer of `qdii_premium_unknown` but operator-semantics distinct: `qdii_premium_unknown` means "fetch failed, data not available — refresh the snapshot"; `qdii_premium_too_high` means "data available, market itself is unfavourable — wait or use alternative venue". The two codes are MUTUALLY EXCLUSIVE in any single call (a `None` premium cannot also be "too high"). Surface in `_BLOCKING_REASON_LABEL` and `_BLOCKING_REMEDIATION` in `decision/report.py`.
- **`qdii_max_premium_pct`** — operator-tunable threshold in `config/discovery.yaml::hard_filters.qdii_max_premium_pct`, schema `src/irc/schemas/discovery.py::HardFilters.qdii_max_premium_pct: float = Field(default=QDII_MAX_PREMIUM_DEFAULT, gt=0, le=1)`. Default `QDII_MAX_PREMIUM_DEFAULT: Final[float] = 0.05` (5% premium ceiling; matches the existing `qdii_premium_unknown` remediation text "QDII feeders frequently trade 5–15% above NAV"). Units: ratio, not percent. Comparison is strict-greater (`premium > threshold` blocks; equality at the boundary is accepted, mirroring `FOREIGN_HEAVY_THRESHOLD` precedent). Hardcoded `Final` constant in `schemas/discovery.py` so the magic number has a name; YAML override is the operator surface. **`gt=0` invariant:** zero is never a meaningful threshold — it would silently block every QDII buy candidate with any positive premium; Pydantic rejects `0` and negatives at validation time so misconfiguration fails loudly rather than producing wrong-decision output.
- **`QDII_PREMIUM_THRESHOLD_PCT`** — module-level `Final[float]` re-export in `src/irc/memo/qdii_premium_lines.py`, bound `= QDII_MAX_PREMIUM_DEFAULT` (NOT a fresh literal). Single locus the memo §5 溢价 column footnote, §6 marker block, §7 hard-block prefix, and `qdii_premium.json::threshold_pct` all read from. The alias guarantees the display value can never drift from the decision-gate value (`qdii_max_premium_pct`); a unit test asserts `QDII_PREMIUM_THRESHOLD_PCT is QDII_MAX_PREMIUM_DEFAULT`. See [ADR 0006](docs/adr/0006-qdii-premium-memo-surface.md).
- **溢价 column (picks-table §5)** — 13th column inserted between `单次定投上限` and `触发状态` in the memo §5 picks-table; rendered by `_format_qdii_premium_cell` in `src/irc/memo/picks_table.py`. Cell contents: `—` for non-QDII rows (`qdii_premium_pct is None`); `0.00%（场外申赎）` for off-exchange QDII feeders (synthetic-zero per off-exchange synthetic-zero policy — the `（场外申赎）` suffix disambiguates "structurally NAV-tracking" from "on-exchange happened to be 0%"); signed `+{pct:.2f}%` / `-{pct:.2f}%` otherwise (sign always rendered so the operator never mistakes premium for discount). The sell-side values (`trim_review`/`exit_review`/`review`) require `is_holding == True` (you cannot trim what you do not own). _Avoid_: "sell signal" (the signal is `risk_action`; `portfolio_action` is its decision-layer rendering), conflating with `score_action`.
- **`map_portfolio_action` (risk_action → portfolio_action precedence)** — the single pure mapper `map_portfolio_action(*, risk_action, score_action, allocation_selected, is_holding, blocking_reasons) -> PortfolioAction` (`src/irc/decision/portfolio_action.py`). Fixed precedence (ADR 0015 §2, corrected by P0-3): sell-side branches PRECEDE the `blocking_reasons` short-circuit — buy-side blockers block BUYING, not selling what you already hold. (a) `exit_review ∧ is_holding ⇒ exit_review`; (b) `trim_review ∧ is_holding ⇒ trim_review`; (c) `review_required ∧ is_holding ⇒ review`; (d) `blocking_reasons` non-empty ⇒ `no_trade`; (e) `score_action ∈ {buy_candidate, strong_buy_candidate} ∧ allocation_selected ⇒ buy`; (f) else `no_trade`. The `review_required → review` mapping (NOT `trim`/`exit`) preserves `discipline.py`'s "drawdown/under_pressure NEVER auto-sells" semantics end-to-end. The `is_holding` gate on (a)/(b)/(c) is load-bearing: `derive_risk_action` can return `trim_review`/`exit_review` for a NON-holding (the legacy `overweight` branch, `discipline.py`), so without the gate an unheld overheated instrument would render as a trim — the mapper, not the discipline derivation, enforces the holdings-only contract. Does NOT touch `thesis_state` (ADR 0003 setter rule) or Policy B publishability.

Synthesizer prompt (`src/irc/memo/synthesizer.py`) recognises the marker and instructs the LLM to leave the block verbatim — same treatment as the other 5 existing marker pairs (`IRC_PICKS_TABLE_*`, `IRC_EVIDENCE_GAP_*`, `IRC_EXECUTION_LINES_*`, `IRC_MACRO_LINES_*`, `IRC_GOLD_EVIDENCE_*`). NOT enforced by `memo/auditor.py` (which is an LLM content reviewer, not a structural gate); two-run byte-equality regression coverage lives in the existing publishable-set lockdown.
- **`weighted_overlap_pct`** — pure metric `weighted_overlap_pct(A, B) = Σ_{s ∈ topN(A) ∩ topN(B)} min(w_A[s], w_B[s])` where `w_*[s]` is `ConstituentAnalysis.weight_pct` (**percent units**, 0.0–100.0, NOT a fraction) and `topN` is the Top-`CONCENTRATION_TOP_N` (default 10) constituents of each `ActiveFundSnapshot` ranked by `weight_pct` descending with `symbol` ascending tiebreaker. Result is in percent units, range `[0.0, min(Σw_A_topN, Σw_B_topN)]`. **Symmetric**: `weighted_overlap_pct(A, B) == weighted_overlap_pct(B, A)`. Defined in `src/irc/memo/concentration.py`. When `len(A.constituent_analyses) < CONCENTRATION_TOP_N` the `topN(A)` set is just `A.constituent_analyses` after the rank sort (no padding); symmetry preserved.
- **`ConcentrationPair`** — frozen dataclass in `src/irc/memo/concentration.py` carrying one pairwise-overlap record: `(instrument_id_a: str, instrument_id_b: str, name_cn_a: str, name_cn_b: str, overlap_pct: float, shared_symbols: tuple[str, ...])`. Class-level invariant `instrument_id_a < instrument_id_b` (strict, alphabetical) — the factory sorts the two IDs before assignment so the two argument-orderings of the same fund pair produce byte-identical records. `overlap_pct` is `round(weighted_overlap_pct, 1)` set ONCE at construction (never re-rounded downstream — pins determinism by construction). `shared_symbols` sorted ASC. Produced by `compute_concentration_pairs(active_picks)`; rows where the metric `>= CONCENTRATION_OVERLAP_PCT_THRESHOLD` (30.0 percent units, hardcoded `Final` constant, mirrors `FOREIGN_HEAVY_THRESHOLD` precedent — `>=` boundary inclusive) survive.

## Macro excerpt rendering

- **Deterministic theme excerpt** — the byte-deterministic prose slice rendered after a theme name in memo §2 `本周宏观研究要点` bullets and in the §3 `IRC_GOLD_EVIDENCE_BEGIN/END` block. Built by `_summary_from_theme_report(report, *, max_chars=400)` in `src/irc/commands/gold_cmd.py`: first strip the `# <theme>` heading + `## Citations` footer via `extract_prose_from_report_md`; then call `_first_prose_paragraph(prose, *, max_chars)` to skip subheadings/bold-only lines and accumulate a paragraph-shaped excerpt; then truncate to `max_chars` with `…` suffix. The result lands in `ThemeReportRef.summary` and flows verbatim through `gold_regime.json["evidence"]` and the memo §2/§3 renderers. Same string is read by both surfaces — no per-surface re-extraction. See [ADR 0008](docs/adr/0008-macro-research-excerpt-depth.md).
- **Macro excerpt depth (skip-rule + paragraph accumulator)** — the two-stage extraction algorithm inside `_first_prose_paragraph`. **Skip rule (a)** drops any line whose `stripped` form (i) starts with `##` (catches `## subheading` AND `### subsubheading` AND deeper — the top-level `# theme` is already stripped by `extract_prose_from_report_md`), or (ii) matches `re.fullmatch(r"\*\*[^*]+\*\*", stripped)` / `re.fullmatch(r"__[^_]+__", stripped)` (bold-only line with NO trailing prose — lines like `**政策优化信号**：…` have trailing prose and DO NOT skip), or (iii) is empty BEFORE any prose line has entered the buffer. **Accumulator rule (b)** locates the first non-skip prose line, strips a leading bullet marker (`- `, `* `, `+ `) if present, and then continues collecting subsequent non-skip lines (bullet markers similarly stripped on each line) until ONE of: (i) `≥3` sentence-ending punctuation marks `{".", "。", "！", "!", "?", "？"}` are present in the buffer, (ii) the joined buffer reaches `≥150` visible characters (excluding leading/trailing whitespace), or (iii) a blank line is encountered AFTER `≥1` prose line is in the buffer (blank lines before the first prose line are skipped, not terminating). Lines joined with a single ASCII space. The hybrid stop-rule guarantees ≥150 chars of substance regardless of report shape (paragraph-shaped vs bullet-list-shaped). **Sentinel disambiguation** (F5 P0 fix, commit `997e418`): when `_first_prose_paragraph` returns the empty string AND `prose.strip()` is also empty (the report body is truly empty after `extract_prose_from_report_md` strips the header + citation footer), `_summary_from_theme_report` returns `（报告为空）`. When `_first_prose_paragraph` returns empty BUT `prose.strip()` is non-empty (every line was caught by the skip-rule — typically a report whose body is only `##`/`###` subheadings and pure-bold subtitles), it returns the DISTINCT sentinel `（报告内容均为标题/小节，未找到正文段落）`. Collapsing both cases into the same string would mask renderer/skip-rule bugs as "no content"; the distinct sentinel makes the over-skip case operator-visible.
- **Macro excerpt char cap** — `max_chars=400` is the production default (raised from pre-F5 `220`). When the accumulated paragraph exceeds the cap, truncate to `max_chars - 1` and append the single horizontal-ellipsis char `…`. The kwarg-only override is preserved so tests pin behaviour at smaller caps. Worst-case section length: 7 themes × 400 chars / ~50 chars-per-line ≈ ~25 visible lines in §2 (`本周宏观研究要点`); empirically themes hit the 150-char floor far more often than the 400-char ceiling, so typical §2 length is ~10–15 lines. Inline `[N]` citation markers from the theme report's own footnote-numbering are STRIPPED from the excerpt (regex `_LLM_REF_MARKER_RE = r"\s*\[\d+\]\s*"`) before accumulation. The ADR initially preferred to leave them verbatim, but the /ship step 8 silent-failure hunter for F5 (fix commit `997e418`) flagged a visual collision with the memo's downstream `[N]` footnote numerals — a reader cannot distinguish an LLM-internal source index from a genuine footnote reference. The strip is also why a 400-char cap cannot land inside a half-bracket. The strip reversal is documented in [ADR 0008](docs/adr/0008-macro-research-excerpt-depth.md) §1.
- **Theme-excerpt citation_id churn** — because `ThesisEvidence.citation_id` is content-derived (ADR 0001 §2: `canonical_url_or_fallback = url or f"{source}:{date}:{summary[:64]}"`) and theme-report evidence has empty `url`, changing the extracted summary changes the row's citation_id. Expected on the F5 deploy run; not a contract violation (ADR 0001 explicitly states no cross-run id stability — same-content/same-id, different-content/different-id). The two-run byte-equality contract (same `data/research/` snapshot → byte-identical `gold_regime.json` → identical ids) is preserved. Operators reviewing diff-of-runs see macro-theme citation_ids change once and then stabilise. Memo §2/§3 `[ref:...]` markers continue to match `gold_regime.json["evidence"]` ids by construction (the same `evidence_by_source` map renders the markers); the publishable-set lockdown integration test (item 008 AC19) stays green.

## Audit gates and enforcement modes

- **`IRC_CITATION_ENFORCE_MODE`** — env var controlling the citation audit gate at the opportunity and memo stages. Values: `{"off","warn","block"}`. Default: `block` (fail-closed). **Canonical-path override:** when `out_dir.resolve().parent.name == "outputs" AND re.fullmatch(r"\d{4}-\d{2}-\d{2}", out_dir.name)`, the env var is ignored and `block` is forced — the gate is non-negotiable on production output paths. Non-canonical paths (scratch / tmp_path / non-`outputs/` directories) honour the env var verbatim; unknown values fall back to `block` with a stderr warning. The shadow log `outputs/<date>/citation_audit.json` is written in ALL modes (including `block` — written immediately before the `RuntimeError` raise) so the audit trail is observable even when the gate is hard-blocking. Single file, shared across both stages: opportunity-stage writes `opportunity_findings` + `constituent_findings` + `discipline_findings` + empty `memo_findings`; memo-stage RMW-overlays `memo_findings`. See item 009 spec §3 AC11–AC13.
- **Citation gate v1 dimension binding** — v1 enforces a STRUCTURAL dual-leg binding at the row level: every publishable row's `thesis_evidence` must carry ≥1 `citation_kind="data"` entry AND ≥1 `citation_kind="information"` entry, both with `scope in {"instrument","constituent"}` and `owner_instrument_id == row.instrument_id`. The diagnosis-doc D2a per-dimension `type` tagging (`valuation_metric` / `heat_metric` / etc.) and the "drop the dimension's conclusion text from rendered output if uncited" renderer behaviour are **deferred to v2** — they require producer-side changes to `derive_thesis_from_evidence` (5 adapters × 4 dimensions) and a `compose_opportunity_report` renderer surface that knows how to drop dimension-specific text. V1 ships the row-blocking finding shape; v2 will add the dimension-tagging contract and the drop-behaviour renderer. See item 009 spec §5 D1 + §6 Q1, Q5 (both deferred).
- **Prose-audit dual-leg is memo-wide** — `find_uncited_conclusions` (the §5/§7 *prose* gate, distinct from the row-level STRUCTURAL binding above) treats an actionable conclusion about an instrument/constituent as cited when its `data` + `information` legs appear ANYWHERE in the audited memo prose, NOT per-paragraph. Rationale: the deterministic picks-table cell already renders each pick's dual-leg (SAME-3 invariant), so a narrative 各标的补充披露 paragraph that cites only the information leg (gold context / fund reports) is no longer falsely flagged for the NAV `data` leg it carries in the table. Computed once per render by `_instrument_legs_present` / `_constituent_legs_present`, which prescan every `[ref:...]` marker in the audited prose (raw-evidence appendix excluded) against `cited_map` / `constituent_cited_map`. The paragraph-local `wrong_instrument_citation` guard (a paragraph citing a non-co-mentioned owner's marker) stays per-paragraph. Genuinely uncited instruments — legs absent everywhere — are still flagged `uncited_conclusion`. This relaxes only the prose gate's *per-paragraph* strictness; the row-level structural dual-leg binding (and `find_missing_pick_citations` / `find_uncited_discipline_rows`) are unchanged. **Scope:** the relaxation's safety rests on the picks table carrying each PICK's dual-leg, so it is fully covered for picks by the parallel `find_missing_pick_citations` structural gate; the one case it also passes is an actionable prose conclusion about a *non-pick* instrument whose data + info markers happen to appear elsewhere in body prose (rare — non-pick instruments normally surface only in the raw-evidence appendix, which the prescan excludes). Both leg builders gate on `_PUBLISHABLE_SCOPES_MEMO`, so a malformed `asset_class_macro`/`policy`-scoped citation never satisfies a dual-leg.


## Thesis-news scoring

- **`news_summaries` (scoring input)** — `dict[str, tuple[str, ...]]` passed to `run_scoring`, keyed by `instrument_id`. The tuple holds 0–N **theme report summaries** (`ThemeReport.report_md` strings) that the keyword rubric in `src/irc/scoring/factors/thesis_news.py::score_thesis_news` counts `_POS` / `_NEG` lexicon hits against. Empty tuple → factor returns `score=50.0, components={"data_completeness": 0.0, "neutral_default": 1.0}` (the cold-start invariant). Built by `build_news_summaries(reports, watchlist)` at the `score_cmd.run_score` edge from already-persisted `data/research/` reports; **never** populated via live per-instrument fetch (would violate determinism). Pre-F4 production hit the empty-tuple branch for every row because the call site passed `news_summaries={}`. See [ADR 0007](docs/adr/0007-thesis-news-scoring.md).
- **`themes_for_instrument`** — pure function `themes_for_instrument(asset_class: str) -> tuple[str, ...]` in `src/irc/scoring/news_summaries.py`. Returns a sorted, stable tuple of theme names from the fixed set `{us_monetary, us_fiscal_politics, cn_monetary, cn_equity_property_policy, geopolitics, gold_drivers, holdings_sector}`. Mapping is keyed off the **real seven `asset_class` values** present in `config/universe/*.yaml` (`cn_bond_fund`, `cn_equity_fund`, `cn_etf`, `gold`, `hk_etf`, `qdii_global`, `us_etf`) — NOT the invented `cn_a_broad` / `cn_a_sector` / `qdii_us` / `qdii_hk` labels from the F4 spec's first draft. `market` is **not** part of the signature (`cn_on_exchange` vs `cn_off_exchange` does not change which macro themes are thematically relevant). Unknown `asset_class` values return the empty tuple silently — falls back to neutral 50.0 per the empty-input invariant. Locked by [ADR 0007](docs/adr/0007-thesis-news-scoring.md).
- **Theme→asset-class mapping (locked)** — | `asset_class` | mapped themes (sorted ASC) | rationale | |---|---|---| | `gold` | `(geopolitics, gold_drivers, us_monetary)` | gold reacts to safe-haven flows, real yields, USD | | `cn_equity_fund` | `(cn_equity_property_policy, cn_monetary, holdings_sector)` | CN-A active equity reacts to CN policy + user-held sector flow | | `cn_etf` | `(cn_equity_property_policy, cn_monetary, holdings_sector)` | same equity-flavour as cn_equity_fund | | `cn_bond_fund` | `(cn_monetary,)` | bonds rarely differentiate on news beyond rates | | `hk_etf` | `(cn_equity_property_policy, cn_monetary, geopolitics, holdings_sector)` | HK reacts to CN policy + geopolitics; holdings flow applies | | `us_etf` | `(geopolitics, us_fiscal_politics, us_monetary)` | USD-denominated equity reacts to US macro + geopolitics | | `qdii_global` | `(geopolitics, us_fiscal_politics, us_monetary)` | global QDIIs are predominantly USD equity exposure | | else / unknown | `()` | empty tuple → neutral 50.0 fallback; documented in ADR | Order within the tuple is theme-name ASC so two-run byte equality of `scoring.json` holds.
- **`build_news_summaries`** — pure function `build_news_summaries(reports: dict[str, ThemeReport], watchlist: pd.DataFrame) -> dict[str, tuple[str, ...]]` in `src/irc/scoring/news_summaries.py`. For each watchlist row: calls `themes_for_instrument(row.asset_class)`, looks up each theme in `reports`, and emits `report.report_md` for themes where the report **succeeded** (`failure_reason == "" AND report_md != ""`). Themes with empty/failed reports are skipped silently (an empty-string summary would inflate the tuple count without signal). Output per-instrument tuple is sorted by theme name ASC. No filesystem access inside the function — reports are loaded by the command layer via `load_theme_reports` and passed in.

## Filing evidence semantics

- **Filing evidence semantics** — a `ThesisEvidence` row with `type="filing"` is a **disclosure-existence anchor**: the canonical evidence that the issuer published a fiscal-period report on a specific date. It is NOT a quantitative performance claim. Producers emit it with `citation_kind="data"`, `scope="constituent"` (active-fund constituent path) or `scope="instrument"` (legacy `ConstituentSnapshot` path), and a summary that does NOT expose the raw `revenue_yoy` scalar inline. The downstream dual-coverage gate, Policy B rule 3, and `select_citations`'s data slot all consume this row as the load-bearing data-leg for active-fund constituents; the user-facing compliance posture is preserved by the `## 附录·原始证据` appendix caveat (`⚠️ 合规警示：…`), now keyed off the filing-summary template phrase rather than the raw `revenue_yoy=` substring. Normalisation of the `revenue_yoy` scalar to a comparable percentage is **explicitly deferred** to a future fundamentals-data effort. See [ADR 0001 §5 Addendum — Filing evidence semantics](docs/adr/0001-citation-data-model.md).
- **Filing summary template** — locked Chinese phrase rendered by `_evidence_for_constituent` (CN + HK active-fund paths in `fundamentals/snapshot.py`) and the legacy `_filing_evidence` (passive ETF / tracked index path in `opportunity/thesis_evidence.py`) into `ThesisEvidence.summary`: `f"{symbol} {fiscal_period} 财报已披露（口径未核实）"`. Three load-bearing properties: (1) the phrase contains the literal substring `财报已披露（口径未核实）` used as the structural trigger for the appendix's `⚠️ 合规警示` line in `memo/pipeline.py::_format_appendix_line` — renaming the phrase requires changing the trigger in lockstep; (2) the `{symbol} {fiscal_period}` prefix is preserved so the `## 持仓明细` appendix `summary[:24]` fragment (`one_line_view`) renders a stable per-holding identifier; (3) the phrase is byte-identical across CN, HK, and legacy filing emitters so no per-exchange rendering branches diverge.
- **Constituent-scope data evidence (producer mapping)** — the only producer of `ThesisEvidence` with `citation_kind="data"` AND `scope="constituent"` in the V1 codebase is `_evidence_for_constituent` in `fundamentals/snapshot.py` (CN branch at `:341-346`, HK branch at `:392-397`), which emits `type="filing"` per top-N holding. Macro paths produce `scope="asset_class_macro"`; fund-level paths produce `scope="instrument"`. **Dropping `type="filing"` from constituent-scope evidence would cause Policy B rule 3 (`incomplete_constituent_data`) to fire for every active CN fund** not already routed through rule 2.5 (foreign-heavy). This single-producer fact is the structural reason F6's chosen position keeps filings load-bearing and reframes only the display.
- **F6 reframe-vs-drop-vs-normalize rationale** — three options were considered (drop / normalize / reframe) for the cognitive dissonance of inline filing rows showing `revenue_yoy=<raw>` while the appendix carries `⚠️ 合规警示`. **Drop** rejected because Policy B rule 3 would reject ~all CN active funds (see `Constituent-scope data evidence (producer mapping)`). **Normalize** rejected because per-provider unit/accounting conventions are not validated and a confidence claim cannot be backed today (see `Filing evidence semantics`). **Reframe** chosen: producers keep emitting `type="filing"` constituent-scope data-leg rows; the displayed summary is locked to the `Filing summary template` phrase; the appendix caveat trigger shifts from substring `revenue_yoy=` to substring `财报已披露（口径未核实）`. The one-time citation_id re-roll (because `summary[:64]` participates in the hash preimage per ADR 0001 §2) is acknowledged in ADR 0001 §5 Addendum and mirrors F5's documented churn precedent. See [ADR 0001 §5 Addendum — Filing evidence semantics](docs/adr/0001-citation-data-model.md).

## Valuation inputs

- **`consensus_upside_pct`** — pure price-vs-target valuation scalar on `OpportunityInput`: `median(non-None broker target_price) / latest_close − 1`, in **ratio units** (e.g. `0.12` = +12% upside, matching the `qdii_premium_pct` ratio convention — NOT percent units), or `None` when no broker report carries a target price OR `latest_close` is `None`/non-positive. Computed by the pure helper `consensus_upside_pct(reports, latest_close)` in `src/irc/fundamentals/consensus.py` and wired into `populate_inputs`. **Distinct from `_broker_consensus`** (`opportunity/thesis_evidence.py`), which counts broker *rating sentiment* and is an information-leg signal; `consensus_upside_pct` is a *price-target* valuation number and carries no rating semantics. Evaluates to `None` in production today because the EastMoney broker feed (`stock_research_report_em`) drops its target-price column upstream (`BrokerReport.target_price` is honestly `None` on that path); the metric activates automatically when a target-price-bearing source lands (Tushare, deferred to a later item). It is a plain numeric input, **not** `ThesisEvidence` — it has no `scope`/`citation_kind`/`citation_id`, so it never participates in the dual-coverage gate, citation selector, SAME-3, H3, or Policy B. See [ADR 0009](docs/adr/0009-consensus-upside-degrade-to-none.md).
- **`KeyRatios`** — frozen dataclass `(roe, debt_equity, gross_margin, fcf_yield)`, all `float | None`, returned by the pure helper `compute_ratios(financials: FilingDigest) -> KeyRatios` in `src/irc/fundamentals/ratios.py` (funding-analysis item 004). All four are **ratio units** (`0.18` = 18%, matching `gross_margin` / `consensus_upside_pct` / `qdii_premium_pct`). A **multi-field bundle** is realised as a frozen dataclass (not a `dict`), mirroring `IndexValuation` / `FilingDigest` / `BrokerReport`; single-scalar metrics (`consensus_upside_pct`, `fetch_qdii_premium_pct`) stay bare `float | None`. `roe` and `gross_margin` are pass-throughs of `FilingDigest` fields; `debt_equity` and `fcf_yield` are **always `None` in production today** because their balance-sheet / cash-flow / market-cap input line items are not yet fetched (wire-but-degrade-to-`None`, the same contract ADR 0009 records for `consensus_upside_pct` — they self-activate with zero further wiring when a richer source lands). Like `consensus_upside_pct` and `pe_ttm`/`pb`, `KeyRatios` is a **plain numeric input, not `ThesisEvidence`**: it carries no `scope`/`citation_kind`/`citation_id`, never participates in the dual-coverage gate, citation selector, SAME-3, H3, or Policy B, and drives **no state/gate/classifier** (`valuation_state` / `thesis_state` / `core_dca` are untouched — reason-only, the same posture pe/pb keep for lacking peer/history normalisation). See [ADR 0009](docs/adr/0009-consensus-upside-degrade-to-none.md) (the degrade-to-`None` contract this reuses; 004 adds no new ADR).
- **`compute_ratios`** — pure, deterministic helper `compute_ratios(financials: FilingDigest) -> KeyRatios` in `src/irc/fundamentals/ratios.py`. No LLM, no I/O, no logging, no network — same `FilingDigest` in → equal `KeyRatios` out. Explicit NaN + zero/non-positive-denominator screening (mirroring `consensus_upside_pct`); any ratio whose computation would divide by zero/NaN, or whose input is NaN/absent, degrades to `None` (never raises, never fabricates). The companion reason helper renders an optional compact Chinese fragment (e.g. `（ROE 18%·毛利69%，口径未核实）`) emitting **only non-`None`** sub-fields and the empty string when all four are `None` (so today's surface is ROE + gross_margin only); it carries the `口径未核实` caveat per the filing-evidence-semantics posture (filing-derived numbers are disclosure-existence anchors, NOT endorsed performance — ADR 0001 §5) and is kept structurally **separate** from the locked `财报已披露（口径未核实）` filing-summary phrase. This is **index-level only** — per-A-share `pe_ttm`/`pb` are still out of scope (Phase 2). The raw scalars stay reason-only beyond this: `pe_ttm`/`pb` add no state effect of their own (the percentile, not the bare ratio, is what bands), `dividend_yield` stays unconsumed, and the consensus-upside `valuation_fundamental_signal` `core_dca` veto is **unchanged** — it still applies even when the cheap verdict came from the PE-percentile anchor (R5). The inertness contract still holds for the **all-`None` production-today case** (ADR 0009): when no `index_valuation_history` rows are cached and every fundamental input is `None`, the outputs are byte-identical to the NAV-only path (the all-`None` dormancy lock).
- **`valuation_fundamental_signal`** — pure helper in `opportunity/states.py` returning `"cheap" | "rich" | "neutral" | None` from `consensus_upside_pct` only: `"cheap"` when `≥ CHEAP_UPSIDE_THRESHOLD` (0.20), `"rich"` when `≤ RICH_UPSIDE_THRESHOLD` (−0.10, asymmetric/tighter — a DCA system errs slow to call cheap, quick to withhold the cheap label), `"neutral"` between, `None` when `consensus_upside_pct is None` (the production-today case). It is an **augmenting anchor**, not a replacement — it mirrors the `earnings_yield`/`real_yield_10y` anchor: for equity asset classes only it appends a Chinese caveat to the `valuation_state` reason and, **only under corroboration** (signal `"cheap"` AND the percentile path already says `cheap`/`reasonable_low`), moves the state **at most one notch toward cheaper**, never toward more-expensive and never overriding `fair`/`expensive`/`very_expensive`. `pe_ttm`/`pb` participate only in the reason string, never the state decision (no cross-asset percentile context exists). Bonds/gold/QDII are untouched. Thresholds are module-level named constants so future tuning moves them in one place. See ADR 0009 (degrade-to-`None` contract this consumes).
- **Fundamental-aware `core_dca` gate** — `core_dca` retains its `cheap_or_low AND quiet_heat AND intact_thesis AND decent_product` precondition AND is additionally refused when a **fundamental valuation contradiction** is present (`valuation_fundamental_signal == "rich"` while the percentile path still reports `cheap`/`reasonable_low`). The block is threaded via a **single explicit gate**: an optional `valuation_fundamental: Literal["cheap","rich","neutral"] | None = None` parameter on `compose_opportunity_state` (default `None` keeps every existing caller byte-identical); when `"rich"` AND `cheap_or_low`, the composer skips the `core_dca` branch and falls through to `small_watch`. This explicit parameter is NOT belt-and-suspenders — it is load-bearing: AC3 forbids `classify_valuation` from moving any state toward more-expensive, so a genuinely-cheap percentile cannot be demoted to express the contradiction, and the notch-refusal mechanism therefore cannot implement this gate on its own. `valuation_state` itself STAYS `cheap` (the percentile fact is true); only the `opportunity_state` falls through. This is the cheap-AND-intact discipline gate: a position is nominated for core dollar-cost-averaging only when cheap by the percentile band, NOT fundamentally contradicted, with its thesis intact. `valuation_state` is a separate axis from `thesis_state` (set exclusively by `derive_thesis_from_evidence`) and from Policy B publishability — it never leaks into either. Adds no `ThesisEvidence`, no `evidence_gaps`, no citation surface: H3 partition, SAME-3 equality, the dual-coverage gate, and Policy B are structurally untouched.

## Adversarial debate (advisory)

- **Bull/bear debate (`--adversarial`)** — an opt-in opportunity-stage feature (funding-analysis item 005) that, for each **publishable** `OpportunityRow`, runs two sibling LLM halves over the row's already-derived thesis card — a **defend** half (steelman the bull case) and a **falsify** half (steelman the bear case) — and pairs them into a `ThesisDebate`. It is a **reasoning aid only**, never a trading signal, score, factor, or ranking input. It reads `thesis_state` (post-`derive_thesis_from_evidence`) and emits prose; it sets **no** state. Gated by `--adversarial` on `irc opportunity` (`is_flag`, default **OFF**); absent, the stage makes **zero** thesis-LLM calls and is byte-identical to today. On, it issues `2 × n_publishable_rows` thesis-LLM calls. _Avoid_: "adversarial scoring", "debate signal" (it scores nothing).
- **`thesis_defend`** — the LLM task (registered in `config/llm.yaml` + `src/irc/templates/config/llm.yaml` as `{ provider: deepseek, model: deepseek-reasoner }`, identical to `thesis_falsify`) that steelmans the **bull** case for a derived thesis. The defend sibling of `thesis_falsify`. Both halves are **first wired in item 005** — `thesis_falsify` was a registered-but-unwired task slot with no production call-site before 005, so neither half runs on any default path. _Avoid_: "bull oracle", "buy recommender".
- **`DefenseResult`** — frozen dataclass `(arguments: tuple[str, ...])` produced by the defend half, parallel to `research/falsification.py`'s `FalsificationResult(conditions: tuple[str, ...])`: single tuple field, same item-cap + per-item sanitise (strip newlines, length cap) + `except Exception → DefenseResult(arguments=())` graceful degrade. Lives in `src/irc/opportunity/debate.py`. Distinct from the **theme-shaped** `FalsificationResult` in `research/falsification.py` (whose `generate_falsification(thesis_summary: str, route)` argues over free-text *theme* theses); item 005 builds a fresh **card-shaped** defend+falsify runner over `OpportunityRow` fields rather than reaching into `research/`. _Avoid_: conflating the card-shaped `debate.py` falsifier with the theme-shaped `research/falsification.py` one.
- **`ThesisDebate`** — frozen dataclass pairing one publishable row's two halves: `(instrument_id, name_cn, thesis_state, defense: DefenseResult, falsification: FalsificationResult)`. Built per row from the already-derived card; the debate argues over the derived `thesis_state`, never recomputes it. Rendered by the pure deterministic `compose_thesis_debate_markdown(debates) -> str` (same tuple in → byte-identical Markdown out).
- **`thesis_debate.md`** — the **advisory, non-canonical** Markdown artifact written via `atomic_write_text` in `_write_opportunity_outputs` **only when `--adversarial` is on**: one section per publishable row (`### {iid} {name_cn}` → derived `thesis_state` → 看多 (defend) bullets → 看空 (falsify) bullets); a both-halves-empty row renders `（本行未能生成辩论）`. It is **NOT** one of the five canonical artifacts (`opportunity_report.json`, `thesis_cards.yaml`, `discipline_report.md`, `rejections.json`, `memo.md`), is **NOT** read by `irc memo`, adds no field to any of them, produces no `ThesisEvidence` / `[ref:...]` / `evidence_gaps` / `advisory_gaps`, and changes no `thesis_state` / `valuation_state` / `opportunity_state` / `core_dca` / Policy-B verdict. As an LLM-prose artifact it is **exempt** from the two-run byte-equality / deterministic-renderer contract that binds the five canonical artifacts (ADR 0004 §Consequences; item 008 publishable-set lockdown) — those contracts are scoped to the deterministic renderers; an LLM artifact is structurally outside them. Permitted on canonical `outputs/<date>/` paths (unlike `--limit`, it does not corrupt the publishable set). One row's LLM failure degrades to an empty half and never aborts the run or blocks the canonical artifacts (which are written independently of the debate file). _Avoid_: "canonical debate output", "debate report" as a memo/canonical input.

- **`_tushare_call`** — the thin network edge `_tushare_call(token, fn_name, **kwargs)` inside `TushareProvider`'s module, doing `import tushare; ts.pro_api(token); getattr(pro, fn_name)(**kwargs)`. The single monkeypatch seam for unit tests (mirrors `akshare_filing._ak_call` / `akshare_index_valuation._ak_call`) so unit tests never import or hit `tushare`. Tushare is mainland-CN (`api.tushare.pro`) and is called **direct**, NOT through `IRC_HTTPS_PROXY` (same policy as the other AkShare CN calls; only LLM/web/Jina/DXY-via-EastMoney are proxied).
- **`live_tushare` gate** — the double-gated live-test gate for the real Tushare shape: a `live_tushare` pytest marker (registered in `pyproject.toml`; `--strict-markers` requires it) AND `IRC_RUN_LIVE_TUSHARE=1` AND a non-empty `TUSHARE_TOKEN` — all three required; default `pytest` skips. Mirrors the `live_akshare` / `IRC_RUN_LIVE_AKSHARE` family (see **Live test gate**). The mandatory assertion is scoped to filing-digest shape only (`fetch_filing_digest("600519")` returns a `FilingDigest` with ≥1 of `revenue_yoy`/`net_income_yoy` non-`None`); the broker `target_price` smoke is optional because `report_rc` may be paid-tier-gated.
- **Provider seam vs fetch budget** — the Tushare fallback is **NOT metered** against the ADR 0002 §3 preflight fetch budget. `FetchPlan.total_calls()` is a static formula over cold/stale AkShare-fund cardinality computed BEFORE the fetch loop; `FetchBudgetExceeded` raises at preflight independent of which provider executes, and the `fetch_budget_exhausted` run-level fatal sentinel fires pre-build. A Tushare call fires *inside* the already-budgeted `fetch_cn_*` execution, only on a per-constituent miss, and changes neither `total_calls()` nor the sentinel's emission path — the provider abstraction structurally cannot change when/whether the sentinel fires. See [ADR 0010](docs/adr/0010-cn-fundamentals-provider-seam.md).

## Holdings ingest policy

- **`fund_holdings` ingest policy** — wall-clock 30-day staleness gate via `_china_today()` (UTC+8); named-column `INSERT OR REPLACE INTO fund_holdings (...) VALUES (?, ...)` with `executemany` (mirrors `_upsert_prices` / `_upsert_nav` / `_upsert_instruments` precedent — positional `INSERT INTO fund_holdings VALUES (...)` is forbidden in production code so future schema column additions don't silently corrupt data); no-delete-on-empty (`MAX(report_date)` naturally promotes fresh over stale; explicit deletion would create a non-pure side effect and complicate idempotency); no-prune retention (historical quarters accumulate; disk footprint < 1 MB/year). Single source of truth is item 003's `ActiveFundSnapshot` cache for `cn_equity_fund` and (when present) `cn_etf`, with `fetch_cn_etf_holdings` as the AkShare fallback ONLY for `cn_etf` cache-misses. Best-effort enrichment for the scoring layer (`scoring/metrics_loader._latest_holdings_concentration`) — partial failure NEVER blocks `run_ingest` (no `HaltReason`, exit 0 even when 100% of targets fail). Idempotent same-day reruns (fresh table → zero `INSERT` statements). Per-row determinism: rows written in `(weight_pct DESC, holding_ticker ASC)` order so DuckDB rowid is reproducible across two-run rerun. See item 010 spec.

## Narrative fund mining (`irc narrative`)

- **Narrative selector** — a *narrative* (e.g. `compute_metals` / 算力金属) is a curated, frozen **reference basket** of stocks + SW industries loaded from `config/narratives/<name>.yaml` (`NarrativeBasket`, `src/irc/narrative/`). `irc narrative <name>` resolves it to a ranked fund **shortlist by holdings look-through**, then optionally runs the deepest per-fund analysis on the shortlist. The selector sits **in front of** and **reuses** the pipeline's classification cores verbatim — it does NOT touch the fixed `Theme` `Literal`, the `discover→…→opportunity` taxonomy, or the H3 / SAME-3 / citation invariants (rejected the invasive "add a theme" approach by design). New narratives (`ai`, `robots`) need only a new YAML — **no code change**. The seeded `compute_metals` basket is a **DRAFT** pending user approval, then frozen (design §7).
- **Screen → analyze gate** — the cheap **screen** runs by default (also `--screen-only`): per curated-universe fund, `fetch_top_holdings` (AkShare `fund_portfolio_hold_em`, cached at `data/narrative_holdings/`, written via `atomic_write_text`) → pure `score_overlap` (symbol-first, `name_cn`-second, with SW-industry credit; each symbol counted at most once) → pure `rank_shortlist` (keep funds meeting EITHER `min_basket_weight_pct` OR `min_overlap_count`; stable sort `basket-weight desc → overlap-count desc → instrument_id`; truncate `top_n`). Funds with no published holdings go to `<name>_screen_diagnostics.json` with a reason — **never silently dropped** ("no silent caps"). `--min-overlap` overrides the config `min_basket_weight_pct` immutably (`dataclasses.replace`). The slow `--analyze` path is opt-in and runs only over the shortlist.
- **`OverlapResult.basket_weight_pct`** — sums the top-10 weight of BOTH direct basket hits AND SW-industry-credited holdings (not only direct basket names); `overlap_count` likewise counts basket + industry-credit hits.
- **Analyze deepens, then reads cache** — `--analyze` reuses `_build_input → build_opportunity_row → build_thesis_card` (→ `derive_dca_action` + `derive_risk_action`) untouched, per shortlisted fund, then `derive_position_risk_level`. `analyze_fund` itself is **read-only** — it consumes the snapshot cache via `load_active_fund_cache` (mirrors `irc opportunity`; CLAUDE.md "reads cached evidence, does not fetch live") and never fetches. The **command layer** runs **narrative active-fund autobuild** (see below) just ahead of the per-fund loop so the cache `analyze_fund` reads is freshly populated for narrative-discovered `cn_equity_fund` funds; the heavy quarterly `fundamentals snapshot` is still NOT triggered inline. A missing snapshot → `build_opportunity_row`'s `evidence_insufficient` fallback → `position_risk_level = insufficient` (surfaced, never crashed); a per-fund analyze exception degrades that one fund to an `insufficient` `error_report` and continues. If `data/local.duckdb` or a cached quarter is entirely absent, the screen outputs are written first, then an actionable error + rc=2. The report carries real `[ref:{citation_id}]` evidence via `select_citations` (same locked 16-hex format as the opportunity renderers). _Avoid_: "analyze is cache-only" (the read-only stage core is, but the command layer auto-builds first).
- **Narrative active-fund autobuild** — the command-layer build-and-cache step in `narrative_cmd.py` that, before the `--analyze` per-fund loop, builds an `ActiveFundSnapshot` (via `build_snapshot(target, top_n=TOP_N_DEFAULT, provider=provider)` + `write_active_fund_cache(replace(snap, cache_probed_at=<today>), root/"data")`) for shortlist rows whose `asset_class == "cn_equity_fund"` that are **missing** a cached snapshot for the resolved analyze-context quarter. The **same concept** as the opportunity autobuild (ADR 0002) on a different command surface, with an **independent** kill-switch `IRC_NARRATIVE_AUTOBUILD` (default `"1"`; `"0"` restores the legacy read-only-cache-only behaviour exactly). Cache-presence gated (no refetch when the resolved-quarter cache exists), per-fund failure degrades to `insufficient` (never crashes the run), budget-guarded by the shared **Preflight fetch budget** (`FetchBudgetExceeded` / `_fetch_budget`, reused — no narrative-specific knob). It supplies the snapshot ONLY; it does NOT run `evaluate_policy_b` / rule-2.5 stamping (see next entry). _Avoid_: `IRC_OPPORTUNITY_AUTOBUILD` (that switch is for `irc opportunity`; the two are independently togglable).
- **Narrative passive fund-level autobuild** — the **second** command-layer build-and-cache edge in `narrative_cmd.py` (item 002), running alongside the active autobuild just before the `--analyze` loop. For shortlist rows whose **resolved** `LookthroughTarget` is fund-level — `target.kind ∈ (_FUND_LEVEL_KINDS ∪ {qdii_us, qdii_hk, qdii_global}) AND target.provider_symbol` — and that lack a cached `nav/` `FundLevelSnapshot`, it builds via `build_snapshot(target, provider=provider)` (no `top_n` — fund-level fetch ignores it) and writes via `write_nav_cache(replace(snap, cache_probed_at=<today>), root/"data")`, guarded by `source_report_quarter` non-empty AND `"qdii_information_unavailable" not in snap.evidence_gaps` (mirrors `_resolve_fund_level_snapshot`). **Eligibility is decided on the resolved `target.kind`, NOT a hardcoded asset-class list**, and therefore requires the **instrument index** (`map_lookthrough(_build_input(...))`) — it cannot be decided from the bare `ShortlistRow` (which carries no `tracked_index`/`theme`); this is the signature difference from the active autobuild, whose `cn_equity_fund → active_fund` mapping is instrument-independent. A bare `cn_etf`/`cn_equity_fund` row with no resolvable `tracked_index`/`theme` maps to the no-`provider_symbol` terminal `broad_index` default and is correctly skipped (nothing to fetch). Shares the SAME kill-switch (`IRC_NARRATIVE_AUTOBUILD`), the SAME `FetchPlan`/`_fetch_budget` preflight (costed via `FetchPlan.fund_level_misses`, 4 calls each per ADR 0002 §5), and the SAME degrade-never-crash contract as the active autobuild. Policy-B-free (FundLevelSnapshot is fund-level-only). _Avoid_: a second `IRC_NARRATIVE_PASSIVE_AUTOBUILD` switch (rejected — one narrative kill-switch governs both edges).
- **Narrative passive path is theme-independent** — the narrative `--analyze` passive path passes `theme_report=None` to `build_opportunity_row` **by design, not as a gap**. The `FundLevelSnapshot` branch of `derive_thesis_from_evidence` (`thesis_evidence.py:348-373`) reads **only** `snapshot.evidence` + `snapshot.evidence_gaps` and never consults `theme_report`; the dual-coverage gate for a passive ETF is satisfied purely by the fund-level NAV (data leg) + announcement (information leg) records. A passive fund with both legs therefore reaches `thesis_state == "intact"` with no theme report. Genuine theme-report sourcing for a narrative-discovered passive fund (the opportunity path's `load_theme_reports` + `_resolve_research_theme`, keyed by `inp.theme`/asset_class) is a citation-richness enhancement (supplemental `asset_class_macro`-scope evidence), **not** a gate-passing requirement — deferred as a documented follow-up. _Avoid_: reading `theme_report=None` on the narrative passive path as a missing-evidence bug.
- **Narrative path is Policy-B-free** — the narrative `--analyze` path consumes the `ActiveFundSnapshot` through `build_opportunity_row → derive_thesis_from_evidence` only; it deliberately does NOT invoke `evaluate_policy_b`, `_stamp_audit_errors_from_verdict`, or `_stamp_fund_level_evidence_from_verdict` the way `opportunity_cmd.py` does. Rationale: the narrative report has **no dual-coverage gate, no H3 partition, no publishability decision** — `thesis_state` is set exclusively by `derive_thesis_from_evidence` (ADR 0003), and Policy B's gap-codes would have no consumer here. The one observable consequence is that a **foreign-heavy** active fund's narrative report carries only the per-constituent citation legs, not the rule-2.5 fund-level NAV+announcement legs (a citation-completeness gap, not a correctness/publishability defect). Restoring rule-2.5 citation parity in narrative reports is a **documented follow-up**, out of scope for the autobuild item.
- **`position_risk_level`** — a NEW pure, deterministic level ∈ `{low, moderate, elevated, high, insufficient}` for the **prospective-buy** decision, derived by `derive_position_risk_level(view, overlap, metrics)` (`src/irc/narrative/risk.py`). Distinct from `risk_action` (`exit/trim/review`), which targets *held* positions (and is mostly inert — `none` — for a prospective, non-held fund). Drivers escalate severity on a ladder: `valuation_state` (expensive/very_expensive), `heat_state` (crowded/overheated), `thesis_state` (under_pressure/falsified), `product_quality_state` (weak/poor), holdings concentration (top-1/top-3 weight), narrative concentration (a single thin overlap slice), and optional `drawdown_3y`/`volatility` (injected via the `metrics` dict only **when available** — never fabricated; not currently on `OpportunityRow`/`OpportunityInput`). Non-empty `evidence_gaps` always forces `insufficient` (the gate fires before any other driver). The rationale names the dominant drivers, each backed by the same `[ref:…]` citations the opportunity eval emits.
- **Narrative `.md` insufficient-row display discipline (H3 analog)** — on a `position_risk_level == "insufficient"` row, `render_report_md` SUPPRESSES every **earned-conclusion** field and renders a single `⚠️ 证据不足 / insufficient` refresh line naming `evidence_gaps` and pointing at `uv run irc narrative <name> --analyze`. This mirrors the **H3 universal gapped-row invariant**'s conclusion-vs-fact split applied to a single-file surface: H3 partitions *rows across files* (gapped rows → `discipline_report.md` only) and its `render_failure_section` reads only `{instrument_id, name_cn, evidence_gaps, fetch_types_attempted}`; the narrative analog is **display discipline** — "do not DISPLAY unearned conclusions in the human `.md`". SUPPRESS = the action triad (`opportunity_state`/`机会`, `dca_action`, `risk_action`/`风险`), `falsification_triggers`/`证伪触发`, `trim_triggers`/`减仓触发`, `review_cadence`/`复核节奏`, **and the four sub-state verdicts (`估值/热度/逻辑/质量` = `valuation_state`/`heat_state`/`thesis_state`/`product_quality_state`)** — the sub-states are classifier *verdicts* (a row missing only one input still classifies the others, so `估值=expensive` can be a REAL verdict on an insufficient row), exactly the conclusion fields `failure_renderer.py` forbids; field-level suppression (not value-conditional rendering of `evidence_insufficient`) is the H3-faithful rule, mirroring "the renderer's signature is the enforcement mechanism". KEEP = `instrument_id`, `name_cn`, `position_risk_level`, `risk_rationale`, `risk_drivers`, `evidence_gaps` (gap-facts), the `产品驱动` raw `product_metrics` segment (费率/规模/任职/跟踪误差 — numeric data, never a verdict; emitted on its own line), and any partial `thesis_evidence`/`持仓明细` appendix/`证据明细` footnotes (provenance to refresh from, never a conclusion). **`.md`-only** — the `.json` (`render_report_json`/`_report_dict`) is the additive full source of truth (item 003 AC8) and is UNCHANGED. The narrative path is Policy-B-free / no-H3-partition (CONTEXT.md "Narrative path is Policy-B-free"), so this is purely a human-facing display projection, not a data/invariant change. A locked grep test asserts no triad / trigger / cadence / sub-state-verdict token survives on an insufficient block (the enforcement mechanism). _Avoid_: value-conditionally rendering a sub-state only when it equals `evidence_insufficient` (a sub-state is forbidden by field, not by value); treating sub-states as gap-facts.
- **Narrative report is a display-only, non-SAME-3 surface** — `narrative/report.py`'s `render_report_md` is a **separate downstream artifact** that is NOT one of the three surfaces bound by the **SAME-3 invariant** / **ADR 0004 §3** citation-set-equality (those bind only the picks-table 证据 cell, the memo evidence-pool `[ref:...]` markers, and the discipline `_render_section` nested bullets — all in the opportunity/memo pipeline, locked by `tests/memo/test_same_3_invariant.py`, which never imports the narrative renderer). The narrative `.md` inline evidence cell still calls `select_citations(thesis_evidence, cap=3)` so it stays consistent with its own `.json` projection, but the per-fund **`### 证据明细` evidence appendix** (per-constituent `one_line_view` + capped per-constituent refs) and the **`[ref:hex]` footnote table** (resolving every inline/appendix marker from the fund's full evidence pool, deduped + sorted by `citation_id` ascending) are **display-only**: they expose a fuller, NON-capped pool and never enter any citation-set-equality check. This is the same "additive file outside the SAME-3 set" pattern accepted for `thesis_debate.md`. Adding the appendix/footnotes therefore cannot break SAME-3. _Avoid_: treating the narrative `.md` as a fourth SAME-3 surface, or pre-filtering its inline cell to match the appendix.
- **Active-fund `质量=weak` is now a real cost/scale verdict (F-1 floor removed)** — `classify_product_quality` → `_classify_active_quality` (`states.py`) grades an active fund on **manager tenure + cost/scale** (`expense_ratio`, `aum_cny`, `tracking_error`, `premium_discount_pct` via `_passive_quality_score`). `aum_stability_pct` is **optional corroboration**, not a hard gate: when present and `<= _AUM_STABILITY_STRONG_MAX` (0.20) it permits `strong`; its **absence only caps the ceiling at `acceptable`** — it NEVER floors an otherwise-sound product to `weak`. An active fund is `weak` only on a genuine signal: tenure `< 2y`, fewer than 2 cost/scale metrics, or a negative cost/scale score; `evidence_insufficient` when `manager_tenure_years is None`. `aum_stability_pct` is still the documented **universal drop** (`decision/completeness.py:22`: "we do not yet ingest a multi-period AUM history" — `populate_inputs` never sets it, `metrics_loader.py:54` writes `NaN`), so until the F-1 data slice lands **no active fund can reach `strong`** (capped at `acceptable`). Consequence: `质量=weak` on an active-fund surface is now **signal, not noise** — read it together with the `产品驱动` raw drivers (费率/规模/任职/跟踪误差; `None` → `—`). The obsolete `_WEAK_FLOOR_LEGEND` / F-1 disclaimer in the narrative `.md` is **removed**. **Opportunity-state ripple**: a sound active fund that is cheap/quiet/intact + now-`acceptable` reaches `core_dca` instead of being suppressed to `small_watch` (`compose_opportunity_state` `decent_product` gate); this is the intended correction. _Avoid_: re-introducing an `aum_stability_pct`-absence floor; faking a stability value to unlock `strong` (it must stay honest-missing until F-1).

## Spend / balance gate

- **`UsageProfile`** — the per-task usage model the spend estimator consumes: each task's `avg_calls_per_run`, `avg_prompt_tokens`, `avg_completion_tokens`, plus a `samples` count (`spend/types.py`). Together with pricing it is the sole input to a cost estimate. _Avoid_: "cost model", "usage table".
- **Seed profile** — a *cold* `UsageProfile` built from `config/spend_pricing.yaml` seeds, every task `samples==0`. Deliberately high so a fresh install over-estimates (the safe direction for a "do I have enough?" gate). Produced by `spend/profile.py::seed_profile`. _Avoid_: "default profile".
- **Learned profile** — the persisted rolling **EWMA** state at `data/spend/usage_profile.json` (global, NOT date-partitioned): per task `avg_*` + `samples`, refolded at the end of every gated run. The memory of what runs actually cost. _Avoid_: "history", "trained profile".
- **Effective profile** — the runtime `UsageProfile` the estimator actually uses: the **learned profile overlaid on the seed profile**, with seed fallback wherever a task has `samples==0`. Produced by `spend/profile.py::effective_profile(seed, learned_raw)`. Named to mirror **effective balance** so the two halves of the gate read symmetrically — `effective_profile × pricing = estimate`, compared against `effective_balance`. _Avoid_: "blended profile", "merged profile".
- **Effective balance** — a ledger provider's spendable remaining: the human-set anchor in `config/spend_balances.yaml` minus machine-counted consumption since the anchor (`spend/ledger.py::effective_balance`). Wallet: `balance − consumed_since`; quota: `quota − consumed_this_period` (auto-resets each period). _Avoid_: "remaining credits", "available balance".
- **Convergence scope** — only **LLM task** estimates converge (the learned profile is LLM-only); **search** estimates stay **seed-fixed** by design. Search actuals are still captured, but they feed the **ledger** (`consumption.json` decrement) — so the search *balance* is exact while the forward search *unit-estimate* stays the seed. Rationale: DeepSeek dominates cost, search units per run are roughly bounded, and a mis-set search seed is visible as estimate-vs-actual in `spend_actuals.json` (retune by hand). _Avoid_: assuming search estimates self-correct; treating the seed-fixed search estimate as a bug.
- **`CostEntry`** — one completed, **billed** LLM call: `(task, provider, model, prompt_tokens, completion_tokens, latency_ms, ts)`, accumulated via the pure `append_cost` (`llm/cost_tracker.py`). Usage **rides home as data** — returned *up* from the `call_chat` wrapper to the command edge — never collected via a module-global or a mutable sink threaded *down* (that would mutate an argument and leak an effect into a pure core). See [ADR 0013](docs/adr/0013-spend-recorder-usage-as-data.md). _Avoid_: a global/contextvar usage accumulator.
- **`RunActuals` / actuals** — one command's measured paid usage for a run: per-task `(calls, avg_prompt_tokens, avg_completion_tokens)` + per-provider `search_units` (`spend/types.py`). The observation EWMA-folded into the learned profile and decremented from the ledger. _Avoid_: "usage" (ambiguous with the profile).
- **Recorder** — the command-edge step `spend/record_run.py::record_command_run` that, at the end of **every runner that made paid calls** (`research`/`discover`/`score`/`opportunity`/`memo` + standalone `ask`/`eval-funds`/`narrative --analyze`), merges `spend_actuals.json`, EWMA-folds the learned profile, and decrements `consumption.json`. Fires on **success and failure** (`history` holds only billed calls), no-ops when nothing was spent, and derives wallet-vs-quota from `spend_balances.yaml`. _Avoid_: "cost tracker" (that's the pure `CostEntry`/`append_cost` primitive), wiring it to *gated* commands (the trigger is *spends-money*, not *is-gated* — `decision` gates but records nothing).
- **Estimate-vs-actual artifacts** — date-partitioned `outputs/<date>/spend_estimate.json` (the next-run estimate, written **only at the `irc run` gate** — run-only, so per-stage gates can't clobber it) and `outputs/<date>/spend_actuals.json` (cumulative actual usage for the date, accumulated per command). The global rolling state behind both is the learned profile `data/spend/usage_profile.json`. _Avoid_: writing `spend_estimate.json` from standalone commands (it would clobber the run-scope estimate).

## Config: packaged template vs runtime

- **Packaged config template** — a checked-in YAML under `src/irc/templates/config/*.yaml` (e.g. `llm.yaml`, `valuation_buckets.yaml`). This is the **shipped contract / shipped default**: the source of truth for what a fresh install does. Enumerated by `TEMPLATE_FILES` (`config_loader.py`, `_FILENAME_TO_SCHEMA.keys()`), which `irc init` copies and `irc config validate` counts. Regression tests and any "what does the product do out of the box?" documentation MUST read the packaged template, never the runtime copy. _Avoid_: "config file" (ambiguous with the runtime copy), "the YAML".
- **Runtime config** — the operator's working copy at `config/*.yaml`, **gitignored** (`.gitignore:23 config/`) and produced by `irc init` copying the matching packaged template. Operator-editable: a local edit here (e.g. re-routing `memo_synthesis`/`memo_audit` to `deepseek-reasoner`) is a **supported override**, not the shipped default, and is invisible to git. Because it is machine-local, the runtime config is NEVER the source of truth for documentation or regression tests — observing a value there says nothing about the shipped contract. _Avoid_: treating an observed runtime-config value as "what the project does".
- **Memo LLM routing (shipped default)** — the packaged `src/irc/templates/config/llm.yaml` routes `memo_synthesis → { provider: openrouter, model: anthropic/claude-opus-4.7 }` and `memo_audit → { provider: openrouter, model: anthropic/claude-sonnet-4.6 }`. This OpenRouter-Anthropic pairing is what `README.md` documents and what a fresh `irc init` produces; a `deepseek-reasoner` memo routing only ever arises from a local runtime-config override. _Avoid_: "memo uses DeepSeek" (true only of an overridden runtime config, never the shipped default).

## Scheduling & notification (`irc notify-status`, launchd)

- **`RunOutcome`** — the frozen value the notifier classifies: `(run_kind, last_exit_code, pipeline_halted, ingest_stale, actionable_buy_count, trim_count, exit_count, review_count, today_dir_exists)`. The three sell-side counts are `int | None` (`null` = signals never derived, ADR 0015 addendum; never coerced to 0). Assembled at the command edge from the wrapper-supplied exit code + today's `outputs/<date>/` artifacts; it is the **sole** input to `classify_run_outcome` (the classifier reads no file, clock, or env). _Avoid_: "run result", "status object".
- **`NotificationDecision`** — the frozen output of `classify_run_outcome`: `(should_notify, severity, title, body)`. `severity ∈ {failed, halted, stale, action, clean}` in that fixed precedence. Pure projection of `RunOutcome`; both notifier channels format from this single value so macOS and Feishu can never disagree on what fired. _Avoid_: "alert", "message" (that's the rendered string).
- **`Severity` precedence** — the locked ranking `failed > halted > stale > action > clean`. `failed` is any `last_exit_code ∈ {1,2,3,4,5}` (mirrors the pipeline's own exit-code vocabulary — 1 runtime / 2 config / 3 fetch-budget / 4 lock / 5 spend-gate); `halted`/`stale` key off the presence of `PIPELINE_HALTED.md` / `STALE_INGEST.md`; `action` fires on `actionable_buy_count > 0`, on any positive sell-side count, OR on **any `null` sell-side count** (the "sell-side state UNKNOWN" sub-case, ADR 0015 addendum); `clean` is the all-clear. _Avoid_: collapsing the `null`-driven action into `clean`.
- **Missing-today-dir outcome** — when `outputs/<china-today>/` does not exist (the run never started — launchd wrapper crashed before `irc`), the notifier classifies `failed`, never `clean`. The notifier resolves **today** via the same UTC+8 `_china_today()` rule the pipeline writes with, and **must NOT** fall back to the latest prior dir (the `_resolve_output_dir` "latest" fallback used by `irc decision` is a reader convenience that would make the notifier report a stale prior run as today's outcome). _Avoid_: reusing `_resolve_output_dir`'s latest-dir fallback in the notifier.
- **`notify-status` spend-gate exemption** — `irc notify-status` makes **zero** paid API calls and therefore **never calls `preflight_gate`** (the spend gate is opt-in per command, invoked explicitly only inside `ask`/`decision`/`eval-funds`/`narrative`/`run`; commands like `freshness`/`allocate`/`plan`/`gold` already opt out the same way). It cannot return exit 5. _Avoid_: assuming the gate wraps all commands.
- **Daily-light run chain** — the weekday cadence is the **full** `irc run` (which already ends in `…→ opportunity → memo → decision`, `STAGE_NAMES`), NOT a hand-rolled `ingest → opportunity → decision` chain: `irc decision` requires `scoring.json` / `proposed_allocation.yaml` / `trade_plan.yaml` / `memo_traceability.json` (written by `score`/`allocate`/`plan`/`memo`), so the short chain would leave a fresh `outputs/<today>/` missing those and `irc decision` would exit 2 every day. The daily/weekly split is therefore **schedule + trading-day gating**, not a different command chain. _Avoid_: "daily runs ingest→opportunity→decision" (it runs the whole pipeline).
- **Trading-day skip predicate** — pure `should_skip_daily(today, holidays) -> bool`: True on Saturday/Sunday or when `today ∈ holidays`. The wrapper supplies the UTC+8 date and the holiday set read from `config/cn_market_holidays.yaml` (a flat user-maintained `YYYY-MM-DD` list; **absent ⇒ empty set ⇒ weekend-only skip**, documented). Reading the YAML and the clock is the edge; the predicate is pure. _Avoid_: a live exchange-calendar fetch inside the scheduling gate.
- **launchd local-time assumption** — `StartCalendarInterval` fires in the **machine's local timezone**, not UTC+8. The 17:30 daily / Saturday-morning schedules are documented as **machine-local wall-clock targeting the operator's own timezone**; the *date resolution* inside the pipeline stays UTC+8 (`_china_today`). On a non-UTC+8 machine the operator adjusts the plist `Hour`/`Minute` (the ops README states the conversion). _Avoid_: assuming launchd honors China time.
