irc monitor — Validation & Eval Workflow

M0 + M1 + M2 eval layer · daily producer emits eval_trace + ledger & applies the in-run gate · offline irc eval scores artifacts (green suite) and synthetic LLM corpora (live_gated) · M2 adds a property/oracle suite + a panel-only deterministic_scoring recompute row

One artifact, two consumers

  • • irc monitor serializes FundView → eval_trace.json (schema_v1)
  • • Same file feeds the monitor_signal oracle & the ledger writer
  • • It's a serialization gap, not new computation (roadmap §3.6)
  • • Both eval writes are degrade-not-crash — brief always renders

Two eval shapes, one surface

  • • monitor_signal: artifact eval, active, in --all green suite
  • • oracle recompute of compute_signal + citation + NAV completeness
  • • monitor_impact/narrative: live_gated LLM suites, out of --all
  • • rc 0 PASS · 1 WARN · 2 FAIL · 3 SKIPPED

Live suites: double-gated

  • • Gate 1: IRC_RUN_LIVE_LLM_EVAL=1 (else SKIPPED rc 3)
  • • Gate 2: preflight_gate("eval-live") spend budget
  • • Never in the daily run or default --all
  • • Synthetic adversarial corpora ⇒ no judge circularity

Gate, badge & fail-open

  • • Only a fresh FAIL from a gating stage ⇒ EVAL_GATED
  • • Badge: validated / caveated / gated
  • • SKIPPED · absent · stale (14d) → fail-open + visible caveat
  • • M0 gating input = in-run monitor_signal_health (always fresh)
