# Design — Monitor dual-track per-stock valuation + False-Cheap clamp (Follow-up 2)

**Date:** 2026-06-19
**Status:** Approved (brainstorming) — pending spec review
**Surface:** `irc monitor`
**Builds on:** #168 (per-stock drill-down + `flow` factor + per-stock self-history valuation), ADR 0017 (evidence isolation), ADR 0018 (weight/scoring governance), ADR 0019 D4 (this work was explicitly deferred there).
**Origin:** #168 spec §9 *"Out of scope (YAGNI) / staged follow-ups"* and ADR 0019 D4 — the dual-track valuation + False-Cheap clamp, classified evidence-**independent** and built now (the conflict-suppression and flow-reversal guards remain evidence-gated and are NOT in this spec — see §10).

## 1. Problem

The bias-driving **valuation factor** is fund-level: `valuation.py::resolve_valuation_state` returns a *state* via either the index branch (`_resolve_index`, for index-tracking funds) or a look-through branch that aggregates constituents into one *portfolio earnings-yield series* and takes its self-history percentile. Separately, #168 added a **per-stock board valuation** (`holding_metrics.per_stock_valuation`) that is **display-only** — each stock vs its own PE history, with **no aggregation into the factor**.

Two gaps:

1. **Self-history only is value-trap-blind.** A stock cheap vs *its own* (possibly de-rated) history can be expensive vs *its peers* — a classic value trap. The factor cannot see this; nothing compares a holding to its industry.
2. **The per-stock board doesn't drive the bias.** The legible per-stock detail #168 surfaced is decorative; the factor still rides a single fund-aggregate series, so the board and the factor can disagree.

**Goal (ADR 0019 D4, evidence-independent leg).** Re-base the look-through valuation factor as a **bottom-up, per-stock dual-track score** — self-history percentile **and** industry-relative richness — with a **False-Cheap clamp** that neutralizes value traps. All score-level, flowing through the existing linear composite (§9 lock: *"a per-stock score adjustment that flows through the existing linear composite, NOT a fund-level veto"*). The #156/ADR 0015 framing is **retained** — a better-*reasoned* lean, never an order.

## 2. Decisions locked (brainstorming 2026-06-19)

| # | Decision |
|---|---|
| D1 | **Two-tier model.** Valuation guards are **score-level** (inside the linear composite). The post-composite *veto* tier (honesty gates) is separate and **deferred** (§10). This spec touches only the score-level tier. |
| D2 | **Re-base the factor bottom-up.** Add `aggregate_valuation()`: per-stock dual-track score → weight-weighted over covered holdings → the **valuation factor value for look-through active funds**. The aggregation *value* follows `aggregate_flow`'s shape (`Σwᵢvᵢ/Σwᵢ` over covered), but the **coverage gate uses the NAV denominator** (D10), NOT flow's. Index-tracking funds keep `_resolve_index` (no per-stock look-through). |
| D3 | **Dual-track blend = 0.60·self-history + 0.40·industry-richness** (your Layer-1 weights). Both legs in `[-1,+1]`, cheap → positive (bullish), matching the existing valuation sign convention. |
| D4 | **Industry leg = Option A**, EastMoney-coherent. "stock PE vs **industry-average** PE" under ONE taxonomy (东财行业). Sources (probed 2026-06-21, grill Q1): industry-average PE from the market-wide `stock_board_industry_name_em` (1 cached call/day, carries 市盈率); stock→industry **per-symbol** via `stock_individual_info_em` over the top-5 holdings (~15–25 deduped cached calls/run — the **exact `flow_fetch` volume + contract**). **Correction to brainstorming:** no single-call market-wide stock→industry table exists under a taxonomy matching any market-wide PE table — `stock_industry_category_cninfo` returns the *taxonomy tree*, not a stock map. So the stock→industry leg **is per-symbol**, and that is fine: it reuses the proven flow per-symbol cached pattern, NOT a new rate-limit risk. Still NOT a per-peer percentile (Option B, rejected: ~N×constituents fetch) and NOT a sector-blind absolute ceiling (Option D, rejected). |
| D5 | **False-Cheap clamp.** `self_score > 0` (cheap vs own history) **AND** richness `r = stock_pe/industry_avg_pe ≥ _FALSE_CHEAP_RICHNESS` (≈1.2, rich vs peers) → **hard-assign** that stock's `val_score = 0.0` (NEUTRAL), `false_cheap=True`. Clamp to **0, not negative** — the guard removes a false bullish signal, it does not assert bearishness (§9: "clamp to 0/NEUTRAL"). **Q4 — hard-0, NOT `min(blend,0)` (deliberate):** the clamp fires ONLY in the value-trap quadrant (`self>0 ∧ rich-vs-peers`), where the correct stance is to **discard the whole valuation verdict to neutral** (epistemic humility on a detected trap + the noise-prone industry denominator of Q2), NOT to preserve the industry leg's exact magnitude. This means the one cell `self_score=+0.5 ∧ r≥1.2` (where the unclamped blend is already ≈−0.1) is **nudged UP to 0.0 on purpose** — that is not a bug; it is the verdict-discard, and it keeps the §5.D board annotation `→中性` literally true. ADR 0020 must record this rationale verbatim. |
| D6 | **No PEG/DCF.** §9's drop stands; monitor computes neither and the dormant fund-level `valuation_fundamental_signal` (ADR 0012/0009) cannot serve. The industry leg + clamp **is** the False-Cheap mechanism (the table's Layer 1 and Layer 2 merge). |
| D7 | **Valuation weight unchanged** (`.20` on `active_cn_equity`). We re-base the factor's *value*, not its *weight* — no profile/weight-vector change. |
| D8 | **Engine bump `"2"→"3"`** (bias semantics change). **GLOBAL** scalar bump (Q6): all 7 `active_cn_equity` funds change (all look-through → all bottom-up); gold/qdii_global/qdii_china_us_internet are semantically unchanged, so the bump needlessly resets their forward clock — accepted, as per-fund engine versioning isn't worth the complexity on a 10-fund set. Conservative: never conflates changed semantics. Forward-eval isolation targets `"3"`; Follow-up 1's `engine_population` WARN covers the transition. |
| D9 | **Priors as named constants**, documented in ADR 0020 (not auto-tuned, ADR 0018): blend `0.60/0.40`, **monitor coverage floor `0.40`** (Q8 — NOT 0.50; distinct from `lookthrough._COVERAGE_FLOOR=0.50`), `_FALSE_CHEAP_RICHNESS = 1.2`, industry_score bands (`0.70/0.90/1.10/1.20`, Q2). Promote to `config/monitor.yaml` only if later tuned. |
| D10 | **Coverage = fraction of fund NAV.** `covered_weight_ratio = Σ covered weight_pct / 100.0` (ratio of NAV; the `/100` is load-bearing — same as `lookthrough_valuation._coverage_ratio`), **NOT** `aggregate_flow`'s covered/top-holdings denominator. `>=` accepts exactly-at-floor (matches `_meets_floor`). **Q8 — REVISED floor + basket (data-driven, probed 2026-06-21):** (1) **the aggregate uses the FULL disclosed basket (~top-10), NOT flow's top-5** — top-5 NAV coverage is 26–41% across all 7 funds, fatal at any floor; (2) **monitor floor = `0.40`, NOT `0.50`** — at `0.50` the factor fires for **1 of 7** funds (519770) and has been a phantom for 6/7 since the monitor shipped; `0.40` → **6/7** (only 260112, the most diversified at 0.34, stays honest-N/A). The `0.40` is a **deliberate monitor-specific divergence** from opportunity's `0.50`: the monitor valuation is a 0.20-weight *research lean*, not a publishability gate. Recorded in ADR 0020. Coverage-scaled confidence (a 0.41-covered read weaker than 0.54) is a **deferred follow-up**, not in this spec. |

## 3. Scope

- **In:** all `active_cn_equity` funds (per-stock A-share holdings exist). Dual-track + clamp + bottom-up valuation factor apply. **Empirical correction (Q6, verified 2026-06-21 against `instruments`):** ALL 7 active funds — **including 018132 有色金属矿业主题指数A** — currently have `tracked_index = NaN`, so they resolve via the look-through branch and get the bottom-up dual-track. 018132 is index-tracking *by nature* but the data does not record it, so it is NOT on the index path. **Documented limitation:** for a sector-concentrated fund like 018132, holdings ≈ the industry → `r ≈ 1` for all → the industry leg is degenerate and the factor collapses to ~self-only (clamp never fires). Acceptable; a cleaner sector-index read would require populating its `tracked_index` (separate data chore, out of scope).
- **Index valuation branch (`_resolve_index`):** kept for any fund that has a real `tracked_index` AND valuation eligible. **No fund in the live set currently meets both** (270023 has a `tracked_index` but valuation is profile-ineligible). So the index path is exercised in production by none today; its dispatch is still unit-tested via a **synthetic fixture fund** (Q6), not 018132.
- **Out (valuation N/A):** gold (profile-**ineligible** — no valuation factor) / qdii_global (profile-**ineligible**) / qdii_china_us_internet **009225** (valuation **ELIGIBLE @0.20 but N/A**: `path="lookthrough"` with NO `holding_metrics` — its `fund_level` profile builds none — so the feed gate skips it and it stays on the state path → `valuation_no_anchor`, today's behavior). ⚠️ §-correction: qdii_china_us_internet is NOT `profile_ineligible` (`profiles.py` lists `valuation` eligible) — it is eligible-but-N/A.
- **Out of scope:** the entire post-composite veto tier (conflict hard-suppression, flow-reversal guard) — deferred, evidence-gated (§10); Amihud tradability veto (dropped from monitor — a decision-layer concern, ADR 0015); per-peer true-percentile industry comparison (Option B); PEG/DCF (D6).

## 4. Architecture

```
FULL disclosed basket (~top-10) for valuation ┐   (flow stays top-5 — Q8)
stock_valuation_history (cached DuckDB) ─────┼─▶ holding_metrics.py (PURE)
  per-stock self-history PE percentile       │     per-stock StockValuation (self_score)
industry_pe / stock_industry (cache) ────────┘     + industry_score + dual-track val_score + False-Cheap clamp
        ▲                                              │
industry_valuation.py (EDGE, cached/day,               ├─▶ aggregate_valuation → ValuationAggregate (Σwᵢvᵢ/Σwᵢ, coverage gate)
  market-wide tables, never raises)                    ├─▶ factors._valuation (look-through: numeric aggregate; index: state) → composite → bias
                                                        ├─▶ render_drilldown.py → board gains industry + value-trap badge
                                                        └─▶ eval/trace.py → holding_metrics block (schema 4) → determinism + coverage + reconciliation
```

Pure core (`holding_metrics`, `aggregate_valuation`, the dual-track scoring) consumes already-loaded inputs. The only new effect is `industry_valuation` (cached market-wide reads), plus the DuckDB reads the valuation path already does.

## 5. Components

### 5.A `industry_valuation.py` (EDGE + pure parse) — Slice 1
Mirrors `flow_fetch.py`'s contract: never raises, degrades to None/empty, parsed rows (no DataFrame on disk), per-day JSON cache with `ok`/`miss` status, **direct** CN endpoint (no `IRC_HTTPS_PROXY`), light pacing (ADR 0014).
- `fetch_industry_pe(*, cache_dir, today, fetch=None) -> dict[str, float]` — industry → average PE, from the **market-wide** `stock_board_industry_name_em` (1 call, cached/day). ⚠️ its 市盈率 is a single column (averaging method unverified, no median variant) — outlier-sensitivity is a known industry-leg data-quality risk to confirm at impl (see Q2 banding).
- `fetch_stock_industry_map(symbols, *, cache_dir, today, fetch=None) -> dict[str, str]` — symbol → 东财 industry **per-symbol** via `stock_individual_info_em` (~15–25 deduped cached calls/run — the same contract as `flow_fetch`, NOT a single classification table). Non-A-share lines → no mapping → industry leg N/A for them.
- Cache `data/monitor/industry_pe/<today>.json` (market-wide) + `data/monitor/stock_industry/<today>.json` (per-symbol `ok`/`miss`, like flow). ADR 0017: the monitor's OWN cache; no opportunity output files.

### 5.B Dual-track scoring + clamp in `holding_metrics.py` (PURE) — Slice 2
- `self_score ∈ [-1,+1]` = **`valuation_state_score(stock.valuation_state)`** (Q3) — derived from the `valuation_state` field already on `StockValuation`, NOT a fresh percentile→value map. This reuses the existing `percentile → _band → state → {1.0,0.5,0.0,−0.5,−1.0}` ladder verbatim (true "unified vocab"; same ladder the index path uses), so the board's displayed state and `self_score` can never disagree. Self leg N/A (immature / non-positive PE / no series, per #168) → `valuation_state is None` → `valuation_state_score(None) is None` → the stock has **no `val_score`** and is excluded from the aggregate (matches #168 state-None behavior).
- `industry_score ∈ [-1,+1]` from richness `r = stock_pe / industry_avg_pe`: cheaper-than-peers → positive, **additive bands on raw `r`, deliberately ASYMMETRIC** (Q2; matches the codebase's "slow to call cheap, quick to withhold cheap" conservatism — `valuation_fundamental_signal`). Named constants: `r≤0.70→+1.0 · 0.70–0.90→+0.5 · 0.90–1.10→0.0 · 1.10–1.20→−0.5 · r≥1.20→−1.0`. The −1.0 edge is pinned to `_FALSE_CHEAP_RICHNESS` (1.2) so ONE threshold governs both "max rich-vs-peers" and the clamp trigger. No industry mapping / no industry PE → `industry_no_data`. **Denominator robustness (Q2):** `industry_avg_pe` must be `>0` & finite (else `industry_no_data`); verify EM's 市盈率 column is **market-cap-weighted** at impl (cap-weighting is outlier-robust; an arithmetic mean would let a sparse/loss-heavy industry inflate avg PE → false "cheap vs peers" +1.0). Add a breadth guard ONLY if EM proves to use an arithmetic mean — recorded as an ADR 0020 risk, not a pre-built knob.
- `val_score = 0.60·self_score + 0.40·industry_score`. **Industry leg N/A → `val_score = self_score`** (honest 1.0·self fallback; the per-stock `HoldingMetric.industry_reason = "industry_no_data"` — never a fabricated industry leg). `industry_no_data` is a **per-stock `HoldingMetric` reason** (alongside the existing `pe_not_positive`/`pe_immature`/`no_series`), NOT a factor-level N/A reason and **NOT in `KNOWN_NA_REASONS`** — the factor stays eligible on self-only.
- **False-Cheap clamp (D5):** `self_score > 0 AND r ≥ _FALSE_CHEAP_RICHNESS` → `val_score = 0.0`, `false_cheap=True`, reason `false_cheap_clamp`.
- Extend `StockValuation` / `HoldingMetric` with: `industry`, `industry_pe`, `industry_richness` (`r`), `industry_score`, `self_score`, `val_score`, `false_cheap`, and the reason.
- `aggregate_valuation(metrics) -> ValuationAggregate`: operates over the **FULL disclosed basket** (Q8 — NOT flow's top-5; top-5 coverage is fatal). **value** = `Σ(wᵢ·val_scoreᵢ)/Σ(wᵢ)` over holdings with a non-None `val_score` (weight-renormalized — same shape as `aggregate_flow`); **clamped stocks count as covered** (contribute 0). **Coverage uses the NAV denominator (D10):** `covered_weight_ratio = Σ covered weight_pct / 100.0` — the fraction of *fund NAV* covered, matching `lookthrough_valuation._coverage_ratio` (NOT flow's covered/top-weight). Zero covered → `valuation_no_data`; `covered_weight_ratio < 0.40` of NAV (the **monitor floor**, D10/Q8 — NOT 0.50) → `valuation_no_coverage`; else `value, reason=None`. The `0.40` floor is a named monitor constant, distinct from `lookthrough._COVERAGE_FLOOR=0.50`.

### 5.C Factor re-base + scoring — Slice 3
- `factors._valuation`: look-through active funds consume the numeric `ValuationAggregate.value`; index funds keep the state→value path. `_valuation` handles both; `FactorInputs` gains the aggregate as a **trailing, defaulted** field (back-compat with the **2 `src/` construction sites** — `monitor_cmd.py` + retro `eval/backtest.py` — plus the test sites; `backtest.py` already omits `flow=` and rides the trailing default, proving the pattern).
- **Resolver must expose its branch (review P1 — the real gap).** `resolve_valuation_state` dispatches index-vs-look-through *internally* via `_tracked_index_for_fund` and returns only a `ValuationResolution` — **the branch taken is hidden**. And `profile_spec.lookthrough == "active_fund"` is **True for index-tracking active funds too** (e.g. 018132), so it is NOT a sound proxy for "use the bottom-up aggregate." **Locked mechanism (Q5):** add `path: Literal["index","lookthrough"]` to `ValuationResolution` (option (i) — keep dispatch owned by `valuation.py`, do NOT leak `_tracked_index_for_fund` into the command). In the look-through branch **short-circuit**: return `(state=None, cached=False, reason=None, path="lookthrough")` WITHOUT computing the old portfolio-harmonic state (it would be discarded). Gate the numeric-aggregate feed on `path == "lookthrough"` — never on `profile_spec.lookthrough`. `_valuation` branches on `inp.valuation_aggregate is not None` (index funds leave it defaulted `None` → state path).
- **Methodology REPLACEMENT, not a value re-base (Q5).** The old look-through path computed a *portfolio harmonic earnings-yield series* then took today's percentile in that series' own history; the new path is a *cross-sectional weighted mean of per-stock dual-track scores*. Consequences (record in ADR 0020): (1) the factor value moves for look-through funds **even with zero industry data** — there is NO "industry-off ⇒ byte-identical" fallback (the self-only bottom-up mean ≠ the old portfolio percentile); (2) maturity is now gated **per stock**, so a fund near the floor with short-history holdings can newly read `valuation_no_coverage` where it produced a state before — more honest, but a visible behavior change; (3) **no portfolio-harmonic fallback** — under-coverage → honest N/A.
- **Delete the now-dead old path (Q5).** Remove `src/irc/monitor/lookthrough.py` (`lookthrough_valuation_state`), `_resolve_lookthrough` in `valuation.py`, and `tests/monitor/test_lookthrough.py`. (The *opportunity* `lookthrough_valuation.py` — `MetricSeries` / `_pe_series_is_mature` / `fund_valuation_percentile` — STAYS; `holding_metrics` still imports from it.)
- **Factor N/A reasons (reachable branches required).** The bottom-up path adds two new `_NA_*` constants emitted by *real* `_valuation` branches mapped from `ValuationAggregate.reason`: `_NA_VALUATION_NO_DATA = "valuation_no_data"` (zero covered) and `_NA_VALUATION_NO_COVERAGE = "valuation_no_coverage"` (below the NAV floor). The index path keeps `_NA_VALUATION_NO_ANCHOR`. Both new codes **must** join `KNOWN_NA_REASONS` (else `deterministic_health._bad_reasons` FAILs them) **and** be referenced from a branch (else `test_known_na_reasons` reachability fails). `industry_no_data` is NOT among these (per-stock reason — §5.B).
- **Full basket for valuation, top-5 for flow (Q8 structuring).** The valuation aggregate + its board rows need the **full disclosed basket**, but flow shipped on **top-5** and must stay byte-identical (it rides engine "2"→"3" only via the global bump, not a flow re-base). So `_process_fund` builds per-stock metrics over the **full basket** for valuation/board, and computes `aggregate_flow` over the **top-5 weight slice** only (flow fetch volume + value unchanged). Flow fetches stay top-5, so full-basket holdings 6–N carry `flow_no_data` on the board (flow columns blank below top-5) — acceptable; the board's flow section remains a top-5 read. Impl may use two metric tuples or one full tuple with a top-5 flow slice; TDD's choice, but the **reconciliation oracle (§5.E) requires the board to render every full-basket holding that contributes to the valuation aggregate** (else board-sum ≠ factor value).
- **`monitor_cmd._process_fund` wiring (HIGH-RISK — the #168/valuation/heat dark-factor trap).** Feed `aggregate_valuation(holding_metrics)` into `FactorInputs` **only when `path == "lookthrough"` AND `holding_metrics` is non-empty** (Q6 — the tightened gate). The second clause is load-bearing: 009225 (qdii) has `path="lookthrough"` but its `fund_level` profile builds NO `holding_metrics`, so without it 009225 would flip from `valuation_no_anchor` → `valuation_no_data`. With it, 009225 leaves `valuation_aggregate=None` → `_valuation` falls to the state path → `valuation_no_anchor` (today's behavior preserved). The integration test MUST drive the real `_process_fund` and assert: (a) a look-through active fund with A-share holdings gets a **bottom-up valuation `FactorScore` (eligible)** end-to-end; (b) **009225** (lookthrough path, no holding_metrics) stays `valuation_no_anchor` via the state path; (c) a **synthetic index-path fixture fund** (tracked_index set in the test `instruments` table + valuation eligible) rides the **index state** — NOT 018132, which is look-through in production (Q6). Do not merely unit-test the pure aggregate. (Memory: assert factor wiring at `_process_fund`, not just the pure fn — same bug class as flow/valuation/heat going dark.)
- **Valuation weight unchanged** (D7): no `profiles.py` weight-vector change.
- `signal.py`: **no new divergence code** — the False-Cheap is neutralized in-score (the clamped stock contributes 0), so it needs no separate caveat. Surface it instead on the board (§5.D).
- `_ENGINE_VERSION "2"→"3"` in `monitor_cmd.py` (D8). `compute_signal` is unchanged — the re-based value flows through automatically.

### 5.D Report — Slice 3 (with the factor re-base)
- `render_drilldown.py`: board gains `行业 · 行业PE · 行业相对 (r) · 行业分` columns and a **value-trap badge** on clamped rows with a 便宜(自身)/偏贵(行业)→中性 annotation. Roll-up shows the dual-track split (self vs industry legs), which holdings were clamped, **and ALWAYS the industry-leg coverage `行业覆盖 X%`** (fraction of covered-valuation weight whose industry leg resolved) — so the dual-track's actual reach is never hidden, outage or not (Q7).
- Non-gating, **pure** fund-level notes (computed from `holding_metrics`, mirroring #168's broad-outage header-note pattern), not side effects:
  - when a material-weight holding is clamped (transparency);
  - **when industry coverage `< 0.50` of covered-valuation weight** (Q7): `价值陷阱检测数据有限/不可用` — signals that the value-trap guard is dark today so a reader can't mistake an industry-data outage for a genuine all-cheap-vs-peers day. Reuses the `0.50` constant (D10); no new threshold.
- `_EXPLAINER` extended to name the dual-track (估值 = 自身历史 + 行业相对；价值陷阱→中性). Lean language only — no 买入/卖出 (ADR 0015).

### 5.E Eval — Slice 4
- `eval/trace.py`: bump `_SCHEMA_VERSION "3" → "4"`; the `holding_metrics` block gains the industry/self/blend/clamp fields. The valuation factor value is now bottom-up automatically.
- **Determinism** (`eval/determinism.py`): dual-track + clamp reproduce identically on cached re-run. `_bad_reasons` validates only **factor** reasons against `KNOWN_NA_REASONS` (verified — it iterates `factor_scores`, not the per-stock block), so the new **factor** reason `valuation_no_coverage` (and `valuation_no_data`) must be there; the **per-stock** reasons (`industry_no_data`, `false_cheap_clamp`) live in the `holding_metrics` block and are NOT factor reasons — if a per-stock recognition check is added it needs its OWN known-set, never `KNOWN_NA_REASONS`.
- **Coverage/health** (free, `eval monitor_signal`): industry-map coverage %, industry-PE coverage %, `false_cheap` tally per fund.
- **Reconciliation oracle** (`eval/structural.py`): assert the board's weighted dual-track `Σ(wᵢ·val_scoreᵢ)/Σ(wᵢ)` over covered rows equals the `valuation` factor value (4dp) for look-through funds — proves the methodology, mirroring flow's reconciliation. **Reads `val_score` (post-clamp) from the trace `holding_metrics` block, NOT the rendered HTML; requires the full-basket rows (Q8) — a top-5-only board would break the equality.** Clamped rows sum as 0 (covered).

### 5.F Versioning
- `_ENGINE_VERSION "2"→"3"` (D8). Tags new ledger rows so the existing `score_forward(target_engine=…)` filter isolates the v3 population; Follow-up 1's `engine_population` WARN surfaces the transition.

## 6. Invariants & constraints

- **ADR 0017 isolation:** industry data is the monitor's OWN cache (`data/monitor/{industry_pe,stock_industry}/`); pure core, effects at edges; no opportunity output files.
- **Determinism + badges:** the new **factor-level** N/A reasons `valuation_no_data` + `valuation_no_coverage` join `KNOWN_NA_REASONS` (non-caveating, like flow's) with reachable `_valuation` branches. **`industry_no_data` is a per-stock `HoldingMetric` reason, NOT a factor reason** — it is not in `KNOWN_NA_REASONS` (the factor stays eligible on self-only). `false_cheap_clamp` is **not** an N/A either — the stock is covered, score 0; per-stock annotation only.
- **No silent caps:** uncovered holdings and clamped holdings are surfaced on the board with reasons; coverage-floor N/A is explicit; **industry-leg coverage is ALWAYS shown and a sub-0.50 outage fires a non-gating note (Q7)** — a dark value-trap guard is never silent.
- **Framing (ADR 0015 line):** still 研究参考信号，非买卖指令. The board explains *why* a stock is cheap/expensive/trap using lean language; no imperative action, no target weights, no per-instrument order.
- **Size budget:** new fetch in `industry_valuation.py`; dual-track in `holding_metrics.py`; clamp pure; `monitor_cmd` stays thin (wiring only).

## 10. Out of scope (deferred — the evidence-gated veto tier)

Per ADR 0019 D4, the **post-composite veto tier** is judged together against forward evidence that only began accruing at engine `"2"` (and resets to `"3"` here). It is NOT built in this spec:

- **Conflict hard-suppression** — whether an open `valuation_flow_conflict` (cheap-but-being-sold / expensive-but-being-bought) should force the call to `NEUTRAL`/`NO_CALL`. Today it is an informational caveat only (#168). Build only once the forward eval (made trustworthy by Follow-up 1) shows conflicted `ADD_BIAS` calls actually underperform.
- **Flow-reversal sign-agreement guard** — whether a 5d-vs-20d flow sign split should down-weight the flow score. Today the split is *visible* on the board but does not down-weight.
- **Amihud tradability veto** — dropped from the monitor entirely: the fund is the NAV-priced tradeable instrument; constituent illiquidity is a decision-layer (ADR 0015) execution concern, not a research-lean gate.

When forward evidence justifies them, these become a separate spec implementing the two-tier weaken-only post-composite veto (composite produces a provisional bias; the veto layer can only demote `ADD → NEUTRAL`, never strengthen).
