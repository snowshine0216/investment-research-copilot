# ADR 0010 — Pluggable CN-fundamentals provider seam with Tushare as a per-method fallback

**Status:** Accepted (2026-05-31, funding-analysis item 003).
**Builds on:** [ADR 0002 — active-fund fetch engine](0002-active-fund-fetch-engine.md) (§3 preflight budget ledger, left untouched), [ADR 0009 — consensus-upside degrade-to-None](0009-consensus-upside-degrade-to-none.md) (the degrade-to-`None` contract this reuses).
**Spec:** `docs/2026-05-31-funding-analysis/items/003-spec.md`.

## Context

IRC's CN fundamentals are single-sourced on AkShare→EastMoney with no fallback (US/HK have OpenBB; CN does not), and `Settings.tushare_token` is a declared-but-unused `SecretStr` stub (`settings.py:42`). Three CN fetchers carry the load — `fetch_cn_filing_digest`, `fetch_cn_broker_reports` (`fundamentals/akshare_filing.py`), `fetch_cn_index_valuation` (`fundamentals/akshare_index_valuation.py`) — each already obeying a degrade-to-`None`/`()` contract behind a thin `_ak_call` indirection. The single highest-value gap is `BrokerReport.target_price`, which EastMoney's `stock_research_report_em` drops upstream (ADR 0009), so `consensus_upside_pct` is honestly `None` today; a target-price-bearing source (Tushare) activates it.

This ADR records a hard-to-reverse architectural seam (a `Protocol` injected through `build_snapshot` and `populate_inputs` into four call-sites), a surprising fallback semantics (try-AkShare-then-Tushare per method, NOT a config-selectable primary), and a deliberate budget-accounting decision — three things a future reader will otherwise re-litigate.

## Decision

1. **A `CnFundamentalsProvider` `Protocol`** (`src/irc/fundamentals/provider.py`, `@runtime_checkable`) with exactly three methods mirroring the existing fetchers and reusing their frozen return types (`FilingDigest`, `BrokerReport`, `IndexValuation`) — **no new DTOs**. The seam wraps these three CN-fundamentals surfaces only; holdings / NAV / announcements / news stay governed by ADR 0002's engine and are explicitly out of scope.

2. **Tushare is a per-method fallback, NOT a config-selectable primary.** `FallbackProvider(primary, secondary)` calls `primary`; on a *miss* (`None` for digest/index, `()` for brokers) or a `primary` exception it tries `secondary`; if `secondary` also misses or raises it returns `primary`'s miss value. It **never raises** (degrade-to-`None` family, ADR 0009). `default_cn_provider()` returns `AkShareProvider()` when `Settings().tushare_token` is empty, else `FallbackProvider(AkShareProvider(), TushareProvider(token))`. **With no token the result is AkShare-only — byte-identical to today.** There is no YAML knob; provider selection is implicit on token presence. A config-driven global primary swap was rejected: it is more surface for no V1 value and risks changing existing outputs.

3. **The Tushare fallback is NOT metered against the fetch budget (ADR 0002 §3).** The preflight ledger (`FetchPlan.total_calls()`) is a *static formula over cold/stale AkShare-fund cardinality* computed BEFORE the fetch loop; `FetchBudgetExceeded` raises at preflight, independent of which provider executes. A Tushare fallback fires *inside* the already-budgeted `fetch_cn_*` execution, only on a per-constituent miss, and changes neither `total_calls()` nor the `fetch_budget_exhausted` fatal-sentinel emission path. The provider abstraction therefore **structurally cannot change when or whether that sentinel fires** — the load-bearing preflight-abort invariant is preserved. Tushare has its own rate limits and is a separate provider; a Tushare sub-ledger is deferred until/unless Tushare ever becomes primary.

4. **Degrade-to-`None` is the contract, and unconfirmable-offline Tushare methods default to it.** The exact Tushare Pro endpoints (`fina_indicator`/`income` for filing financials, `report_rc` for broker target prices, `index_dailybasic` for index valuation) and their column labels cannot be pinned without a live token; `report_rc` (target prices) is gated behind a points/paid tier. Mapping helpers are written defensively against candidate column sets (the `_PE_COLS`/`_PB_COLS` precedent). A single double-gated live test (`live_tushare` marker + `IRC_RUN_LIVE_TUSHARE=1` + real `TUSHARE_TOKEN`) is the pin-point; its mandatory assertion is scoped to filing-digest only. If the token tier cannot reach `target_price`, the fallback still adds CN filing-digest redundancy and `consensus_upside_pct` simply stays `None` (ADR 0009 unchanged).

## Consequences

- **Behavior-preservation is locked** by a byte-equality regression test: `AkShareProvider` delegates each method verbatim to the existing module function, asserted equal to the direct call on the same stubbed `_ak_call`. No DataFrame parsing is re-implemented in the provider layer.
- **Network isolation:** `TushareProvider` performs all I/O through one `_tushare_call(token, fn_name, **kwargs)` edge doing the local `import tushare`; unit tests monkeypatch it (mirroring `_ak_call`). `FallbackProvider` routing is pure and tested with in-memory fakes — no `tushare` import at module load, no network in unit tests.
- **Proxy:** Tushare (`api.tushare.pro`) is mainland-CN, same domain class as the AkShare CN calls the README/`http_proxy.py` keep direct. It is called **direct**, NOT through `IRC_HTTPS_PROXY`. No `http_proxy.py` change.
- **Citation/gate invariants untouched:** the seam moves *where* the three fetches dispatch from; it emits no new `ThesisEvidence` and changes no `citation_id` preimage. Dual-coverage gate, Policy B / `thesis_state` ownership (ADR 0003), 16-hex citation id (ADR 0001), H3 / SAME-3 (ADR 0004) are structurally unaffected. A Tushare-supplied `target_price` flows only into the numeric `consensus_upside_pct` scalar (ADR 0009), not a citation.
- **Static-profile invariant:** none of the three seam methods touch fund static-profile; `基金概况` is not introduced. The existing grep test (`test_static_profile_invariant.py`) currently scopes only `akshare_fundamentals.py` + `snapshot.py`; item 003 must extend it to also grep the new `provider.py` / `tushare_provider.py` (the spec's "already in scope" claim was false — the test enumerates files explicitly).
- **Negative:** a third provider direction (deeper threading) was avoided by resolving `default_cn_provider()` once at each command edge and threading one `provider` parameter; inner functions keep default-arg construction so existing tests calling them stay valid. The trade-off is a wider-but-shallow signature change across `build_snapshot` / `populate_inputs` and their private `_build_*` chain.
