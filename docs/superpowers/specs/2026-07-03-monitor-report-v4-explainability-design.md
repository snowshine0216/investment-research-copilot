# Design — Monitor report v4 explainability: per-fund caveat reasons, macro direction/why, divergence detail, industry-column fill

**Date:** 2026-07-03
**Status:** Spec — grilled 2026-07-03 (all open decisions resolved in-session); ready for autodev backlog mode (4 items, order WS-3 → WS-1 → WS-2 → WS-4, per-item PRs → feature branch → roll-up PR on user opt-in)
**Surface:** `irc monitor` report rendering + eval gate + EastMoney fetch edges
**Relates to:** report v3 readability (2026-07-02 spec, merged PR #193), CN-egress data-plane light-up (2026-07-02 spec, WS-A merged PR #190), ADR 0019 (flow freshness), ADR 0020 (dual-track valuation), ADR 0021.

## 1. Problem (all four visible in `outputs/2026-07-03/monitor/report.html`)

1. **Caveat opacity.** All 10 funds show `⚠ caveated` but nothing on the fund card says *why*. Root cause today: `apply_eval_gate` (`src/irc/monitor/eval/gate.py:18-19`) returns `GateDecision(..., "caveated", "")` with an **empty reason** on the WARN/UNKNOWN branch (only the FAIL branch collects reasons). The actual cause is run-global: the two LLM-suite healths in `GATING_STAGES_M1` are UNKNOWN-stale (`monitor_impact` last ran 2026-06-17, `monitor_narrative` 2026-06-16 — both > `STALE_AFTER_DAYS`). The validation panel at the bottom shows this, but the chip → panel connection is unstated, and per-fund WARNs (if any) are indistinguishable from the run-global cause.
2. **宏观面速览 lists claims without direction.** Each theme block renders claims as neutral bullets (`render_html.py:_macro_claim_html`). Yet direction data already exists: each fund's `impacts["macro"]` records `{key: theme, impact: −1..+1, confidence, citation_ids}` (e.g. 008986 × gold_drivers = +0.8). The renderer drops it. `attribution_strength` (possible_driver / consistent_with) is also in the trace and dropped.
3. **Risk lines are fixed strings.** `趋势与宏观背离` / `因子分歧较大` come from a static code→text map (`render_factors.py:_DIVERGENCE_CAVEATS`); the reader can't see *which* factors disagree or by how much, even though `SignalRecord.contributions` sits right next to the call site (`render_cards.py:102`).
4. **Empty industry columns.** Two distinct gaps:
   - **行业 (name) missing beyond ~top-5:** the per-symbol `stock/get` fetch throttles out — today's `data/monitor/stock_industry/2026-07-03.json` has only **7 ok symbols** out of ~60 requested (full basket); the per-day cache resets tomorrow so coverage never accumulates (same failure shape as the pre-B2 flow leg). The light-up spec explicitly deferred cross-day caching as a follow-up ("per-day is ~20 proxied calls/run, acceptable" — measured today: not acceptable).
   - **行业PE / r / 行业分 all dark:** `fetch_industry_pe` (board `clist/get`) has produced no cache since **2026-06-30** — empty parses are correctly not cached (D3), but the fetch itself has failed 07-01→07-03 (suspects: tunnel-push2 CONNECT refusal noted in WS-A day-1 ops, or 12:15 throttle pressure from the ~60 per-symbol calls above). With `industry_pe = {}`, every row gets `industry_no_data` and `industry_cover = 0.0`.

## 2. Proposed decisions

| # | Decision | Rationale |
|---|---|---|
| P1 | **Gate carries caveat reasons.** On the WARN/UNKNOWN branch, `apply_eval_gate` builds `reason` from the considered stages: `"monitor_impact: UNKNOWN (stale, 15d); monitor_narrative: UNKNOWN (stale, 16d)"`. `GateDecision.reason` already exists (empty today) → **no schema bump**; the trace `gate.reason` field just stops being empty. | Symmetry with the FAIL branch; zero new types. |
| P2 | **Chip becomes self-explanatory; run-global causes dedupe to the overview.** *(Locked at grill 2026-07-03.)* `render_html._badge`: chip gets `title` tooltip with the P1 reason (Chinese stage labels: `monitor_impact→影响评分质量评估`, `monitor_narrative→叙事质量评估`, `stale→上次质量评估已过期`), and becomes an anchor `<a href="#validation-panel">`. Causes from the two **run-global** LLM-suite stages render ONCE as a 今日速览 line (e.g. `全部基金 caveated：LLM质量评估过期 15/16天 · 周六自动刷新`), NOT repeated on every card. A card-level `为何有保留` line appears only for **fund-specific** causes (`monitor_signal` WARN, e.g. nav gaps). `trace gate.reason` stays per-fund and complete regardless of render dedupe. Validation panel gains a remediation hint for stale suites: `IRC_RUN_LIVE_LLM_EVAL=1 uv run irc eval monitor_impact / monitor_narrative`（受 eval-live 花费闸门约束）. | Ten identical lines train the eye to skip them; the overview is the reader's entry point and phone-visible (no hover). Fund-local lines stay reserved for genuinely local causes. |
| P3 | **Macro direction is deterministic, per (theme × fund) — not per claim.** *(Locked at grill 2026-07-03.)* A theme's direction legitimately differs per fund (geopolitics can be 利多 gold, 利空 QDII tech). Reuse the already-validated `impacts` records: in each theme block each fund chip renders **color + inline signed value** (`008986 +0.8`; green ≥ +0.15 / red ≤ −0.15 / grey between). A fund with **no impact record** for the theme stays uncolored with no number (absence ≠ zero). Confidence stays OFF the chip (trace only; `title` attr as progressive enhancement — the report is read on the phone, hover is not a carrier). One legend line explains the −1..+1 scale. **No new LLM output for direction.** | Direction data already exists, sanitized and production-consumed (it feeds macro_tilt); rendering it is pure. Per-claim LLM direction would be globally ambiguous and adds injection surface. |
| P4 | **Surface `attribution_strength` per claim.** Tag each bullet: `可能主因` (possible_driver) vs `方向一致` (consistent_with) vs `已证实归因` (supported_attribution). Data already in trace; renderer-only. | Free honesty: tells the reader which items the model thinks *moved* markets vs merely rhyme with them. |
| P5 | **Theme-level mechanism sentence via narrative prompt 2→3.** *(Reshaped + locked at grill 2026-07-03 — replaces the deferred per-claim variant.)* `monitor_narrative` (already ONE run-global call) additionally emits one length-capped mechanism clause **per theme** (`"mechanism"`, ≤ ~60 chars, e.g. `就业数据疲软→加息预期降温→利多黄金/成长`), rendered under the theme header as `对本组基金的传导：…`. Validator (`narrative_macro.py`) gains the field (required-optional: missing/oversized/imperative-bearing → theme renders without it, never fails the block); sanitizer applies; **the LLM explains, never scores** — direction remains deterministic from impacts (P3). `monitor_narrative` live-eval corpus extended to cover the field. Per-claim why stays out of scope. | The user's ask is explicitly "positive/negative AND why"; impacts carry no rationale field (verified), so the mechanism must come from an LLM — the theme level is the right granularity (~5-6 clauses/run, trivial tokens) and the run-global narrative call is the cheapest carrier. |
| P6 | **Divergence caveats parametrized.** New pure `divergence_caveat_detail(code, contributions)` in `render_factors.py` (static map retained as fallback for unknown codes / missing factors): <br>· `trend_macro_conflict` → `趋势与宏观背离：趋势 −0.75（价格动能向下） vs 宏观 +0.62（新闻/宏观偏多）` <br>· `low_factor_agreement` → `因子分歧较大：偏多 heat +0.30、macro_tilt +0.62 ↔ 偏空 trend −0.75` (list every present factor, grouped by sign; if triggered by dispersion alone, say `强度离散 σ=0.56 ≥ 0.5`) <br>· `trend_valuation_conflict` / `valuation_flow_conflict` analogous. Call site `render_cards.py:102` already holds the `SignalRecord`. | The data is already on hand at the call site; this answers "哪些因子、往哪边、差多少" exactly. |
| P7 | **Industry names go batch-first.** Extend the `ulist.np` batch fields `f12,f14,f184` → `+f127` at **both existing call sites** — the 12:15 brief's provisional-flow call (`monitor_cmd._provisional_flow_note` → `fetch_flow_today_batch`) and the 15:45 `flow-capture` job (verified: the brief already makes this call; no new call is added). Parsed `f127` values merge into a **new cross-day industry map store** (`data/monitor/stock_industry_map.json`, per-symbol `{industry, seen_at}`, refresh-on-seen, serve-while-stale ≤ 30d — industry membership is quasi-static; byte-stable atomic writes, corrupt-file degrade-to-empty). `holding_metrics` consumes the merged map; the per-symbol `stock/get` path is **kept only as fallback** for symbols absent from batch responses (its per-day cache stays; in steady state it fires ~never). | Fills 行业 for the FULL basket in the same single call that already works (flow_cover 1.0 today via `batch_today`); eliminates ~60 push2 calls/day → directly reduces the throttle pressure that's killing the board-PE fetch (P8). |
| P8 | **Board-PE resilience: fetch first + serve-while-stale ≤ 3 trading days.** (a) Reorder the 12:15 brief so the one paginated `clist/get` board-PE fetch runs BEFORE any remaining per-symbol storm. (b) On empty fetch, fall back to the most recent cached day ≤ 3 trading days old, tagged in the report (`板块PE 引用 2026-06-30 · 3个交易日前`) and surfaced as a freshness state (FRESH / STALE-N / DARK — same vocabulary as the flow leg, ADR 0019 / D-B6). (c) Optionally also fetch board PE in the 15:45 `flow-capture` job (rested window) so next morning's fallback is at worst 1 day old. | Industry-average PE moves slowly; a 3-day-old denominator with an honest age tag beats a dark column. Mirrors the already-accepted flow STALE-N design. |
| P9 | **No `_ENGINE_VERSION` bump.** P7/P8 are data-availability changes (same class as flow DARK→FRESH, ADR 0019 precedent and light-up D4): the dual-track math is untouched; the industry leg lighting up (or consuming ≤3td-old board PE) redefines no value stream. P1–P6 are render/gate-reason/prompt only. **One eval-trace `schema_version` bump 6→7** covering all additive fields of this spec together: the `board_pe_freshness` marker (P8b), the per-theme `mechanism` field in `macro_narrative` (P5), and the now-populated (shape-unchanged) `gate.reason` (P1). Narrative **prompt version 2→3** (P5). | Consistent with the locked bump policy; forward-ledger comparability preserved; one bump, not three. |

## 3. Workstreams & slice plan (TDD; test files mirror sources)

**WS-1 — Caveat transparency (P1+P2 + weekly eval refresh)** — small-medium
1. `staleness.resolve_health`: age-stamp the stale reason (`stale, 15d` — it already holds `now` and `ran_at`); `eval/gate.py`: caveated-branch reason assembly (unit tests: WARN-only, UNKNOWN-stale with age, mixed, validated stays empty).
2. `render_html.py`: chip tooltip + anchor; Chinese stage-label map; run-global causes dedupe to ONE 今日速览 line; card `为何有保留` line only for fund-specific (`monitor_signal`) causes; panel remediation hint. Render tests: overview line present when suites stale, absent when fresh; card line only on per-fund WARN.
3. `ops/launchd/run-weekly.sh`: append the two live LLM eval runs (`IRC_RUN_LIVE_LLM_EVAL=1`), best-effort — eval failure logs but never fails the weekly step; spend gate applies unchanged.

**WS-2 — Macro direction + mechanism (P3+P4+P5)** — medium
1. Pure join: `(macro_narrative blocks, per-fund impacts)` → per-theme `{fund_id: impact}` (unit tests: fund missing theme → chip uncolored/no number, empty impacts, sign classes at ±0.15).
2. `render_html._macro_theme_section` / `_macro_claim_html`: colored inline-signed fund chips + legend; per-claim strength tag (可能主因/方向一致/已证实归因). Snapshot-style render tests.
3. `narrative_macro.py`: prompt 2→3 with per-theme `mechanism` field; validator (length cap, sanitizer, imperative check; missing/invalid → theme renders without it); render `对本组基金的传导：…` line; `monitor_narrative` live-eval corpus extension for the field.

**WS-3 — Divergence detail (P6)** — small
1. `render_factors.divergence_caveat_detail` pure fn (tests per code incl. dispersion-only trigger, missing factor → fallback string, unknown code → escaped raw).
2. `render_cards.py:102` call-site swap.

**WS-4 — Industry fill (P7+P8)** — medium-large, touches fetch edges
1. `flow_batch_fetch.py`: `+f127` in fields; `parse_ulist` returns `(flow, industry)` per secid (fixture tests incl. missing f127). Verify f184 values byte-identical with the extra field (one live spot-check through the proxy before merge).
2. New `industry_map_store.py` (cross-day, refresh-on-seen, ≤30d serve-while-stale, byte-stable atomic writes, corrupt-file degrade) + `monitor_cmd` merge order: store → batch f127 → per-symbol fallback.
3. `industry_valuation.fetch_industry_pe`: serve-while-stale ≤3td fallback (+ freshness state); `monitor_cmd` fetch reordering; optional capture-job board-PE fetch.
4. Renderer: 行业PE age tag; valuation_coverage panel gains the freshness state; KNOWN_NA_REASONS unchanged (industry_no_data still covers the DARK case).
5. Docs: ADR 0020 addendum (board-PE staleness), CONTEXT.md if a new term lands (*Board-PE freshness state*), `docs/monitor/README.md` ops manual + workflow diagram sync (per standing convention).

**Order (locked at grill): WS-3 → WS-1 → WS-2 → WS-4** — one autodev backlog run, per-item PRs into a feature branch, roll-up PR to main on user opt-in. If WS-4 stalls on live endpoints, items 1–3 still land.

**Post-merge ops (in order):** one manual `IRC_RUN_LIVE_LLM_EVAL=1 uv run irc eval monitor_impact` + `monitor_narrative` (clears today's caveats) → reinstall the weekly launchd agent (wrapper changed) → next 12:15 brief: verify overview caveat line gone, 行业 column filled full-basket, board-PE freshness state rendered.

## 4. Acceptance (Tier 1, pre-merge)

- Every caveated fund's reason is reachable without hover on a phone: run-global causes as ONE overview line, fund-specific causes on the card; `validated` funds show none; gate unit tests cover all badge branches; `gate.reason` non-empty in trace for every caveated fund.
- Each macro theme block shows per-fund inline-signed direction chips whose values equal the trace `impacts` records (reconciliation test), strength tags on every claim, and a mechanism line when prompt-v3 output validates (and no line — never a crash — when it doesn't).
- Each divergence caveat names the factors with their signed values; report contains no bare `各因子方向/强度不一致` when contributions are available.
- On a fixture with full batch-f127 coverage: 行业 filled for every holdings row; with board-PE cache 2 days old: 行业PE filled + age tag rendered + freshness state in panel; with cache 4+ td old: column dark with `industry_no_data`.
- `flow_reconciliation` byte-identical (P7 must not perturb f184 parsing); `_ENGINE_VERSION` untouched; ruff + full `tests/monitor/` + `tests/commands/` (per-file — whole-dir hangs) green.
