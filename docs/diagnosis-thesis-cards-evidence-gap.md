## 1. Problem statement

### 1.1 What the user observed

1. Every card in `thesis_cards.yaml` carries `evidence_gaps: [missing_constituent_snapshot]`.
2. The cards are nearly identical inside each asset class — every `cn_equity_fund` card cites the same 2 news items (about gold), every `cn_bond_fund` cites the same 2 央行逆回购 news items.
3. `discovered_watchlist.csv` is much richer — each row has a 3-sentence, per-instrument reason with `cited_refs` — so the asymmetry between the two files is conspicuous.
4. `memo.md` and `discipline_report.md` draw conclusions ("减速定投", "暂停加仓", "证据不完整或信号不一致…") but never cite news, annual reports, or quarterly reports to back them up.

### 1.2 What the user requires going forward

> "for all the conclusion drawn in `memo.md` and `discipline_report.md` we MUST have both **data** + **information** (news, annual report, quarterly report) supported, and should **reference** these information. ALSO for these funds, it has several stock holded, so the analysis should ALSO be done on these individual stock. ANALYZE ONE by ONE."

Three hard requirements:

1. **Citation requirement.** Every conclusion (per instrument, **across every asset class** — active funds, ETFs, gold, bonds, QDII US/HK/global) must reference at least one piece of supporting information — news URL, filing (annual/quarterly report), broker note — alongside the quantitative state. **V1 partial coverage note:** V1 delivers citation coverage for cn_equity_fund, cn_etf, tracked CN indices, gold, and cn_bond_fund. All QDII variants (us/hk/global) are excluded from V1 actionable outputs due to a single shared blocker — **missing information-kind evidence adapters** for non-CN markets (no US/HK news adapter for qdii_us/hk; no qdii_global-specific information source). Data-leg adapters exist for all three (verified post-PR #54 — see Q8 in §5). V1 does NOT satisfy the all-asset-class mandate for QDII; this gap is explicitly tracked and V1 must not be considered complete until QDII V2 ships. QDII rows in V1 output receive `evidence_gaps=["qdii_information_unavailable"]` and appear only in the discipline failure section with no investment-action conclusions.
2. **Drill-through requirement.** For each active fund, the analysis must descend to the individual stocks it holds (top holdings) and surface stock-level evidence in the conclusion.
3. **Per-stock granularity ("one by one").** Each disclosed top holding must carry its own filing/broker/news evidence in a structured field — not just an aggregate per-fund evidence list.

**V1 systematic exclusion footnote (Q9.b).** Beyond the QDII V1 exclusion above, Policy B's weight-aware quorum gate (Slice H2) systematically excludes one additional fund class: **active CN funds whose top-5 holdings by weight are predominantly US stocks**. Reason: V1 ships no US news / broker-commentary adapter (only CN via `fetch_cn_stock_news` and HK via the new `fetch_hk_stock_news` from Q2), so US holdings can supply data leg (EDGAR filings) but cannot satisfy the per-constituent info-leg quorum. Affected funds receive `evidence_gaps=["insufficient_info_coverage_top_half"]`, flow to discipline failure section, and are listed in `outputs/{date}/rejections.json` with per-constituent breakdown. **HK-heavy funds** (e.g., `501025 鹏华中证香港银行指数(LOF)A`) WILL pass once Q2's HK news adapter is live, provided HK news returns non-empty for the material HK names. **V2 prerequisite to admit US-heavy funds:** add a US news / broker-commentary adapter producing `scope="constituent", citation_kind="information"` evidence; then re-evaluate the V1 exclusion list. A once-per-run summary line in `discipline_report.md` near the failure section names this exclusion explicitly (Slice H2.v2).

### 1.3 Why it matters

Without per-instrument citations, the discipline report and memo are reduced to verdicts without justification — an investor cannot audit *why* a fund moved to "暂停加仓" beyond "估值偏高或热度偏高". Without stock-level drill-through, the active funds are treated as black boxes, even though their disclosed top-10 holdings are public and fetchable.

### 2.3 Why `discovered_watchlist.csv` is richer than `thesis_cards.yaml`

Three structural reasons, not one bug.

| Aspect | `discovered_watchlist.csv` | `thesis_cards.yaml` |
|---|---|---|
| Producer | `discovery/reason_writer.py::write_reason` | `opportunity/cards.py::build_thesis_card` + `opportunity/report.py::compose_thesis_cards_yaml` |
| LLM call | **Yes** — route `watchlist_reason`, one call per instrument | **No** — pure function over dataclasses |
| Input evidence | `context.raw_refs` — per-instrument refs from the data manifest (`akshare:prices:518880:2026-05-21`, `akshare:instruments:518880:2026-05-21`, …) | A shared `theme_report` per asset class (no per-instrument context) + optional `snapshot` (blocked for active funds; build not wired) |
| Grounding gate | `if not cited: continue` — response is **rejected** unless ≥1 raw_ref appears verbatim; retries up to N times (`reason_writer.py:107-110`) | None — whatever the pure function returns is serialized |
| Per-instrument granularity | One LLM call per instrument | Same theme_report for every fund in the asset class |
| Failure mode | Returns `None`, instrument silently dropped (so every row that exists IS grounded) | Returns an `evidence_insufficient` card with empty/generic evidence list — still serialized |

In short: discovery is **LLM-grounded with per-instrument refs**; opportunity is **pure-function with per-asset-class refs**. Even if the constituent layer were fixed, per-fund news routing would still produce identical citations across funds in the same sector. The fix must reach into the opportunity-to-memo serialization chain, not just the constituent fetcher.

### 2.4 Why the memo and discipline_report carry no citations

Because of defects #8–#12 above:

- `memo.md` §5 "精选标的" comes from `picks_table.render_picks_table(pick_rows)`, whose `PickRow` dataclass has no citations column. The Raw Evidence appendix comes from `build_evidence_pool`, which collapses each instrument to one line of state codes + scores. The LLM synthesizer cannot quote a news URL because (a) the picks row has no citation slot, and (b) the evidence pool never carries thesis_evidence. Even when `OpportunityRow.thesis_evidence` is populated (e.g. some QDII rows do get news from `geopolitics.md`), those citations are dropped at `_row_to_dict` and never reach the JSON the memo reads.
- `discipline_report.md` is rendered by `_render_section`, which only emits `instrument_id name | opportunity_state | dca=X | risk=Y | note_cn`. No citations, and `DisciplineRow` has no field that could carry them anyway.

## 3. Fix plan (revised after Codex review)

### Design principles applied throughout

1. **Data model first.** Before changing renderers, make the structured field exist on every dataclass on the path. No regex citation-counting.
2. **Plumb the `LookthroughTarget` object, not its `display_cn` string.** The current code stringifies the lookthrough target at the entrance of `_build_rows`, losing `kind` and `key`. Multiple defects flow from this.
3. **Build on cache miss, not only at ingest time.** If the active-fund snapshot is missing, `_build_rows` must trigger `build_snapshot()` (with a budget/limit knob) — otherwise A1 stays dead until a separate ingest is added.
4. **Coverage = CN equity funds + CN ETFs + tracked CN indices + gold + cn_bond_fund.** Active funds get fund-level holdings AND per-stock analysis. Gold/bond/CN ETF/tracked indices get per-asset-class snapshots serialized so memo + discipline see them. **All QDII variants (`qdii_us`, `qdii_hk`, `qdii_global`) are explicitly out of V1 scope** — single shared blocker per Q8: missing information-kind evidence adapters for non-CN markets. Data-leg adapters exist for all three (post-PR #54). V1 disposition for ALL QDII: `evidence_gaps=["qdii_information_unavailable"]`, `opportunity_state="exclude"`, flow to the discipline failure section via H3's failure renderer (investment-action fields are never emitted). Add a canonical-output test: any QDII row with `opportunity_state="core_dca"` must not appear in memo.md or discipline.md as an actionable conclusion. V1 claims no all-asset-class coverage; all QDII is tracked as V2 work.
5. **Citation enforcement = structured equality, not regex.** Audit fails when any pick has zero entries in its serialized `thesis_evidence`, or when a prose `[ref:...]` marker doesn't map to a real entry.

Filing digest (`fetch_cn_filing_digest`) counts as `citation_kind="data"` only — the current adapter uses `ak.stock_financial_abstract` which returns Sina numeric summary fields (revenue, net-income, margins), not full filing text or management commentary. **Broker alone counts as `citation_kind="information"` only** — analyst opinion, not primary data. **News alone counts as `citation_kind="information"` only.** A constituent has dual coverage when: filing succeeded (data leg) AND at least one of broker/news succeeded (information leg). Filing-only fails the information gate. Broker+news-only fails the data gate. A fund where all material holdings have only filing data (no broker AND no news) fails H2's dual-coverage check. A fund where all material holdings have only broker + news evidence (no filing or NAV data) will fail H2's per-constituent coverage check. This is consistent with D2a's classification — see also the regression test in E6(b) that broker-only fails the data gate. A fund where all material holdings have only news evidence (no filing, no broker) will fail H2's per-constituent coverage check and flow to the discipline failure section.
8. **Audit on the picks table specifically — resolved as closed invariant.** D2a enforces both a data leg (`citation_kind="data"` — filing/NAV metrics) AND an information leg (`citation_kind="information"` — news/broker) for every pick. News-only picks fail the data gate; filing-only picks fail the information gate. This supersedes the earlier question of "just ≥1 citation" — the dual-leg requirement is the invariant. Not open; see E6(b) and E6(c) for the blocking regression tests.
