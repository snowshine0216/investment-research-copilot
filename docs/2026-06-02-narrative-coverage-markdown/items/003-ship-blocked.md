2. **Dangling constituent footnote refs (latent bug).** `_appendix_constituent_line` emits `[ref:{cid}]` from `c.evidence`, but `_footnote_lines` builds the appendix from `r.thesis_evidence` only. Production holds `c.evidence ⊆ thesis_evidence` via `_flatten_analyses`, but it's UNENFORCED at the render boundary → a report whose constituent evidence isn't mirrored into `thesis_evidence` emits inline refs with no footnote, silently. FIX: build the footnote pool from the UNION of `r.thesis_evidence` + every `c.evidence` (deduped) so every inline ref (fund-level or constituent) resolves regardless. Test: a constituent ref absent from `thesis_evidence` still resolves in `### 证据明细`.
3. **Non-deterministic dedup (latent determinism risk, ADR 0004).** `_footnote_lines` does `{ev.citation_id: ev for ev in ...}` — last-writer-wins on input order. `citation_kind` is excluded from the citation_id hash preimage (ADR 0001), so two distinct records can share a `citation_id`; the survivor's footnote text is then input-order-dependent. FIX: pick the survivor deterministically (stable sort key before the dict build, or merge). Test: two records sharing a citation_id in either input order → exactly one footnote, byte-identical.

Rendering real-looking driver numbers next to `weak` can mislead. M2's intent was "so the reader can judge." FIX (accurate, in-scope, NO scorer change): add a concise report-level legend noting `质量` is presently a structural floor pending F-1, so readers should weight the surfaced `产品驱动` over the `weak` label. Do NOT per-fund over-claim; do NOT change `classify_product_quality`. Test: the legend appears.
